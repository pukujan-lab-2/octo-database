## PDD / product goal

A person can authenticate with Google and see only the workspaces they are allowed to use, with roles represented cleanly enough to support owner/admin/operator/member and later agent/service principals without implementing enterprise tenancy.

## User roles for this slice

Implement one owner and workspace memberships needed for this flow. Expanded admin/operator/agent roles belong to the slices that use them.

## Success condition

From a fresh browser:
1. approved owner signs in with Google;
2. Octo creates/resolves one stable user principal;
3. dashboard lists exactly authorized workspaces;
4. entering Personal works;
5. a second unapproved account cannot enumerate or access Personal by URL/API guessing;
6. logout/session revocation blocks subsequent access;
7. browser contains no service-role/master credential.

## SDD / implementation boundary

Canonical tables:
- users/principals;
- workspaces;
- workspace_memberships;
- optional role/capability mapping.

Authentication proves identity; authorization decides workspace access. Google tokens are not the authorization model. The API/server must derive workspace access from canonical membership state and RLS/server policy.

Frontend may display roles but never decides them.

## Scope control

In scope:
- Google OAuth/OIDC login;

- role representation;

Out of scope:

- multi-region auth;

Do not build SaaS tenancy infrastructure here.
