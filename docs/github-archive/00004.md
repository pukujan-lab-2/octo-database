## PDD / product goal

An authorized workspace member can upload, list, open/download, and delete an active file through Octo without learning provider credentials or depending on a specific R2 object key.

## Success condition

- upload a file into Personal;
- bytes exist in private R2 storage;
- canonical Postgres metadata points to it;
- another authorized session can list/open it by logical file ID;
- unauthorized workspace/user cannot enumerate/download it;
- delete removes or tombstones according to policy without orphaning canonical state;
- no R2 secret appears in browser/app logs.

## SDD / data contract

Canonical `files` metadata includes at minimum:
- id;
- workspace_id;
- owner/created_by principal;
- name;
- MIME/type;
- size;
- provider;
- provider locator/key;
- lifecycle/status;
- timestamps;
- optional content hash.

Storage-provider interface must separate logical API from provider implementation: put/get/delete/exists plus capability for later archive/restore extension.

Postgres owns metadata/authorization; R2 owns bytes.

### Implementation Plan & Architecture — Slice 2 (File Catalog & R2 Active Storage)

Per owner direction, proceeding with the implementation of Slice 2:

1. **Database Schema (`octo.files`)**:
   - Table `octo.files` with columns: `id`, `workspace_id`, `created_by`, `name`, `mime_type`, `size_bytes`, `provider`, `storage_key`, `status`, `content_hash`, `metadata`, `created_at`, `updated_at`.
   - **Row-Level Security (RLS)**:
     - `SELECT`: only workspace members can list and view files in authorized workspaces (`octo.is_workspace_member(workspace_id)`).
     - `INSERT`: only workspace members with role `owner`, `admin`, or `operator` can upload files.
     - `UPDATE`/`DELETE`: restricted to `owner` or `admin`.
     - Zero leakage across workspaces.

2. **R2 Active Storage Provider**:
   - Uses S3-compatible client connecting to the configured Cloudflare R2 bucket.
   - Storage keys partitioned by workspace: `workspaces/{workspace_id}/{file_id}/{sanitized_name}`.
   - Operations: `putObject`, `getObject`, `deleteObject`, `headObject`, and presigned upload/download URLs.

3. **Platform API**:
   - Server-mediated file upload, download, listing, and deletion by logical UUID file ID.
   - Credentials remain in server environment; browsers and clients receive only short-lived signed URLs or stream endpoints.

4. **Verification**:
   - Live PostgreSQL 16 RLS verification.
   - Integration tests with real R2 bucket operations.
   - Type-checks (`tsc --noEmit`), linting, and vitest suites.
