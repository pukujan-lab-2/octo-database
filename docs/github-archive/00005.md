## Summary

Build the first polished user-facing application: a private image/video gallery over the same workspace/file APIs. The gallery is a separate UI surface from the admin/control console, not separate infrastructure.

## PDD / product goal

Family/personal users can browse albums visually, load thumbnails quickly, open full images, and play browser-supported videos without seeing infrastructure/admin controls.

## Success condition

A signed-in member opens a 20+ item album:
- thumbnails render without downloading every full original;
- full image opens on click;
- browser-supported video plays;
- inaccessible media from another workspace never appears;
- retrying thumbnail generation does not create duplicate logical derivatives;
- originals remain private.

## SDD / media design

Gallery consumes logical file/media endpoints. Thumbnail artifacts are derived, cacheable, and rebuildable from originals. Metadata may record thumbnail variant/provider locator but original file remains canonical evidence.

Keep admin/control routes separate from gallery routes and authorization surfaces.

## Scope control

In scope:
- album/folder listing;
- grid thumbnails;
- full-screen image view;
- basic video playback;
- responsive family-friendly UI;
- thumbnail generation/cache.

Out of scope:
- public sharing (next slice);
- HLS/transcoding pipeline unless native playback is insufficient for a test fixture;
- image editing;
- social feed/comments;
- face recognition;
- automatic semantic tagging.
