## Summary

Allow an owner to share exactly one album/folder through a scoped link without granting access to the admin console or the rest of the workspace. Read-only sharing is the v1 default; editable/upload sharing is a separate later permission.

## Identity and lineage

- Parent: #1.

## PDD / product goal

A recipient with only a high-entropy share URL can view the intended album and nothing else; the owner can expire/revoke access immediately.

## Success condition

- owner creates a read-only album share;
- logged-out recipient can view only that album;
- sibling albums/workspace routes are inaccessible;
- raw token is not stored in audit logs;
- revoke causes subsequent authorization to fail;
- expiry boundary works at the configured instant;
- optional future edit/upload scope is represented separately and is off by default.

## SDD / authorization design

Canonical share record contains:
- share ID;
- workspace_id;
- target resource/folder/album ID;
- token hash (not raw token);
- permission/scope;
- valid_from;
- optional valid_until;
- created/recorded time;
- revoked_at/status;
- audit metadata.

Authorization resolves token→share→target scope before issuing media access. Underlying R2/Drive location is irrelevant.

## Scope control

In scope:
- anonymous read-only scoped links;
- expiry;
- revocation;
- optional authenticated/specific-user mode if naturally compatible;
- audit event.

Out of scope:
- anonymous workspace browsing;
- public bucket;
- general bearer token with workspace scope;
- edit/upload by default;
- search across private content;
- link analytics product.
