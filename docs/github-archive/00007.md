## Summary

Use Cloudflare R2 as active/hot object storage and Google Drive as the cold/archive tier while preserving one stable logical file identity. Archival is a controlled state transition, not a blind copy/delete script.

## PDD / product goal

Move an eligible inactive file R2→Drive and restore it Drive→R2 without data loss, broken authorization, or changed logical file ID.

## Success condition

For one real gallery image:
1. file starts active in R2;
2. archive job copies to Drive;
3. destination integrity is verified before any R2 deletion;
4. canonical metadata records archive state/provider locator;
5. R2 source is removed only after verified durable copy + recoverable metadata transition;
6. gallery can later request the same logical file ID;
7. restore recreates active R2 bytes and updates state;
8. image opens normally again;
9. interruption at each boundary converges to a recoverable state.

## SDD / lifecycle state machine

Suggested states:
- active_r2
- archiving
- archived_drive
- restoring
- reconciliation_required
- deleting / deleted where applicable

Canonical state lives in PostgreSQL. R2/Drive hold bytes. Workers must use idempotent operations and content hash/size verification where available.

Archive sequence:
select eligible → mark/lease job → copy → verify destination → persist provider/state transition → delete active copy → confirm final state.

Never delete the only verified copy.

## Scope control

In scope:
- Drive OAuth server-side connection;
- dedicated app-controlled archive area;
- archive eligibility policy;
- copy/verify/update/delete;
- restore;
- reconciliation of partial failures;
- permanent/important retention opt-out.

Out of scope:
- relying on Drive revision history as canonical versioning;
- exact 30-day hardcoded rule;
- zero-knowledge encryption;
- bulk cold migration before correctness proof;
- multi-cloud archive replication.

## TDD

Failure matrix:
- R2 read fails before copy;
- Drive upload fails;
- Drive upload succeeds but verification fails;
- Drive upload verifies but DB update fails;
- DB state changes but R2 delete fails;
- restore Drive read fails;
- restore R2 write succeeds but DB update fails;
- duplicate retry after each case.

Security:
- archive worker has no broader user-facing scope than needed;
- Drive refresh token never reaches browser/agent;
- workspace authorization remains identical after provider change.
