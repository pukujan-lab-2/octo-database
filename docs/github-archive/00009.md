## Summary

Give AI agents and automation scoped machine identities that use the same Octo platform boundary as human-facing apps. An agent token proves a principal and capabilities; it never contains infrastructure master credentials or the whole system manual.

## PDD / product goal

Create/revoke an agent identity for one workspace, let it discover permitted Octo tools/capabilities, and enforce scopes server-side for every call.

## Success condition

A read-only agent token:
- can call capability discovery;
- can list/read allowed workspace files;
- cannot delete;
- cannot enter another workspace;
- cannot retrieve Google refresh token, R2 secret, DB password, Supabase service secret, or other platform credentials;
- produces attributable audit records;
- stops working after revocation/expiry.

## SDD / principal and token model

Agent/service principals use canonical principal IDs and workspace memberships/capability grants. Token record stores hash/fingerprint, scopes, issuer/creator, created/expiry/revocation times, and optional workspace restriction.

Capability discovery describes **how to call Octo**, while token claims/DB grants define **what this principal may do**.

Platform API/tool gateway performs authorization before provider actions. Agents do not own key rotation policy.

## Scope control

In scope:
- agent/service principal;
- scoped platform token;
- capability discovery/tool schemas;
- audit attribution;
- expiry/revocation;
- minimal rotation flow.

Out of scope:
- unrestricted admin agent;
- raw R2/Drive/Postgres credentials;
- autonomous secret rotation by LLM;
- general secrets broker;
- arbitrary external tool execution.

### API Architecture Log — Account-Wide and Workspace-Scoped Access

Per owner instruction, establishing the platform API key engine supporting both workspace-level and account-wide database access:

1. **API Key Model (`octo.api_keys`)**:
   - `id UUID PRIMARY KEY`
   - `key_hash TEXT UNIQUE NOT NULL` (SHA-256 hash of secret key)
   - `prefix TEXT NOT NULL` (`octo_live_...`)
   - `name TEXT NOT NULL`
   - `principal_id UUID NOT NULL REFERENCES octo.principals(id)`
   - `workspace_id UUID REFERENCES octo.workspaces(id)`:
     - **When NULL**: **Account-Wide API Key**, granting access to any workspace authorized for the parent principal.
     - **When SET**: **Workspace-Scoped API Key**, strictly restricted to the specified workspace.
   - `role TEXT`: assigned role for this token (capped at principal's actual role).
   - `scopes TEXT[]`: granular capability scopes (`read`, `write`, `files`, `admin`).
   - `expires_at TIMESTAMPTZ`
   - `last_used_at TIMESTAMPTZ`

2. **Guest Login & Database Access**:
   - Guest authentication enabled alongside Google OAuth: creates a guest principal (`is_guest: true`) with an auto-provisioned personal workspace and active session token.
   - Allows immediate database, file catalog, and API usage without requiring pre-configured OAuth credentials.

3. **API Gateway & Verification**:
   - Gateway middleware authenticates incoming bearer tokens (`Bearer octo_live_...`).
   - Verifies key hash, checks expiration, updates `last_used_at`, and enforces either account-wide or workspace-scoped authorization.
