## PDD / product goal

Ingest an immutable document version, retrieve semantically relevant chunks within one workspace, and let an agent trace an answer back to the exact source/version and embedding/chunker configuration.

## Success condition

For a known PDF:
- source/version is registered;
- extraction/chunks are produced with provenance;
- embeddings are stored with model/version/dimensions/chunker metadata;
- query returns the expected relevant source chunk;
- another workspace's chunks are never returned;
- re-embedding under a new config does not erase historical configuration identity;
- deleting/rebuilding derived embeddings does not destroy source/version records.

### Retrieval Verification Caveat & Status Note

For precision and audit accuracy:
- **Database & SQL Matching**: The pgvector HNSW index, schema hierarchy, deterministic chunking, and workspace-scoped `octo.match_chunks` retrieval were verified against PostgreSQL 16 using deterministic test vectors in SQL.
- **HTTP Ingest & Query Endpoints**: The platform routes (`/api/rag/documents` and `/api/rag/query`) use a provider-neutral client (`src/rag/embeddings.ts`) that strictly fails closed with `503 EMBEDDING_PROVIDER_NOT_CONFIGURED` when `OCTO_EMBEDDING_API_KEY` is unset.
- **Provider Status**: The InferHub API key available in this workspace does not expose an `/embeddings` endpoint (returns 404), so live semantic embeddings remain pending configuration of an external OpenAI-compatible embedding provider key.
