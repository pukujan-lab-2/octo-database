## Summary

Add an optional epistemic research schema for claims, beliefs, evidence, relations, provenance, and bitemporal history. This capability is for projects where “what was believed when” differs from “what is now believed was true then.”

## Identity and lineage

- Parent: #1.
- Task ID: OCTO-0900.
- Depends on: #10.
- Downstream: #12.

## Goal

Represent changing knowledge without overwriting history, while keeping PostgreSQL the canonical epistemic ledger and source evidence immutable/addressable.

## Success condition

For one policy narrative:
- claim A is recorded as believed at T1;
- later evidence contradicts/qualifies it at T2;
- a new claim supersedes it at T3;
- query 1 answers “what did perspective P believe at T2?”;
- query 2 answers “with current knowledge, what do we now consider valid at T2?”;
- results differ correctly and cite evidence/version provenance;
- another perspective can hold a different belief state for the same claim.

## SDD / canonical schema

At minimum:
- entities;
- claims;
- beliefs/perspectives;
- evidence/source references;
- claim_evidence;
- claim_relations;
- valid/world time;
- transaction/recorded time;
- provenance to run/source/version.

Relations may include SUPPORTS, CONTRADICTS, SUPERSEDES, QUALIFIES, DERIVED_FROM, DUPLICATES/REFINES as needed.

Belief is not one mutable column on claim.
