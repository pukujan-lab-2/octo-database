## Summary

An owner can share exactly one album through a scoped read-only link. The recipient needs no account, sees only the shared album, and the owner can revoke or expire access at will.

## Verified behaviour (live PostgreSQL 16 + browser)

| Check | Result |
| --- | --- |
| Anonymous album access (no auth header) | 200, returns the shared album |
| Anonymous media fetch via share-signed URL | 200, 306 B thumbnail derivative |
| Forged / unknown token | 404 |
| After revoke: share | 404 |
| After revoke: previously valid media URL | 401 |
| Not-yet-valid share | 404 |
| Share token used as workspace bearer | 401 |
| Anonymous workspace / keys / files routes | 401 |

Playwright proves the same flow in a real browser: a logged-out recipient sees only the album with no workspace, member, key, or admin surface, and revocation is immediate.

## Design
- **Token hash only**: the table stores a SHA-256 hash; the raw token is returned exactly once at creation and never persisted or logged.
- **Share-scoped media signing**: media URLs carry no principal and are capped at the share's own expiry, so revoking a link also kills the media it served.
- **Uniform 404**: unknown, revoked, not-yet-valid, and expired links are indistinguishable, so responses cannot probe which links existed.
- **Upload is off by default** and must be requested explicitly.
