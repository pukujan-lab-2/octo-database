## Design
- **State machine**: `queued → running → completed`, with retryable failure returning via a controlled `running → queued` transition. Terminal states never move.
- **Idempotency** is a unique `(workspace_id, job_type, idempotency_key)` constraint, so a repeated enqueue returns the original row instead of a second logical job.
- **Lease-based recovery**: `claim_job` uses `FOR UPDATE SKIP LOCKED` with a lease, so exactly one worker gets a job and a crashed worker's job is reclaimed rather than lost or duplicated.
- **Retry accounting**: exponential backoff to `max_attempts`; malformed payloads and unknown job types fail permanently so they cannot retry forever.
- **No client-side transitions**: RLS grants members read-only access; only the trusted server moves state.
