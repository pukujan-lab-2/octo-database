## Summary

Agents and automation now get scoped machine identities on the same Octo platform boundary as human apps. A token proves a principal and its capabilities; it never carries infrastructure credentials.

## Verified behaviour (live)

- Read-only token capability discovery: 5 read/files actions, destructive ones absent
- Read-only token lists files: 200
- Read-only token deletes a file: 403
- Read-only token uploads: 403
- Token reaches another workspace: 403
- Infrastructure credential strings in discovery payload: 0
- Agent upload/delete appear in the activity feed attributed to the agent principal
- After DELETE /api/keys/:id: 401
- Revoking a non-owned key: 404
- Unknown scope at mint time: 400

## Design
- Discovery describes how; scopes decide what. The capability list is filtered to granted scopes for readability, but enforcement is server-side on every route.
- Non-destructive by default: new tokens get read, write, files; delete and admin must be requested explicitly.
- Revocable: added DELETE /api/keys/:id. A token that cannot be withdrawn is a liability, and its absence was a real gap found during verification.
- Injection-resistant: the indirect prompt-injection test proves a retrieved document instructing the agent to delete everything and print the secrets changes nothing, because authority lives in token scopes.
