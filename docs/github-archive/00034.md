## Summary

Adds an optional epistemic schema so a project can distinguish *what was believed when* from *what is now considered true then*, without overwriting history.

## Verified behaviour (live PostgreSQL 16)

| Question | Answer |
| --- | --- |
| Analyst A, recorded 2026-06-01, valid 2026-06-15 | believes (0.900) |
| Analyst A, recorded 2027-01-01, valid 2026-06-15 | disbelieves (0.850) |
| Analyst B, recorded 2027-01-01, valid 2026-06-15 | uncertain (0.400) |
| Claims current at recorded 2026-06-01 | 2 claims (original + qualification) |
| Claims current at recorded 2027-01-01 | a different 2 (qualification + supersession) |

Same valid instant, different recorded instant yields a different belief; same instants, different perspective yields a different belief state.

Additional checks: all three claim rows survive T1/T2/T3 (nothing overwritten); deleting every belief left 3 claims, 1 evidence row, and provenance (run-3) intact; an outsider principal saw 0 claims and 0 evidence rows from another workspace.

## Design
- **Two independent time axes**: valid time (when it is true in the world) and recorded time (when Octo believed it). Corrections close intervals rather than updating rows.
- **Belief is not a column on claim**: it lives in a perspective-keyed table, which is what makes perspective-specific state possible.
- **Evidence is an immutable reference** (file/version, locator, quote, hash) — no bytes and no provider credentials.
- **Optional by construction**: additive schema, separate from gallery/files.
