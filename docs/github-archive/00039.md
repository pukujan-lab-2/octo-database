## Summary

Implements Slice 5 (#7): the R2↔Google-Drive archive lifecycle, so a file's bytes move between the active R2 tier and a Google Drive cold tier **without changing its logical file id**. This closes the gap left by PR #24, which shipped only verification scripts — `origin/main` had no Drive provider, no archive state, and no archive route, and `.env.example` still read "not yet implemented".

Archival is a controlled state transition, per the issue: copy → verify the destination → persist canonical state → **only then** delete the source.

- **Migration** `20261001060000_slice5_archive_lifecycle.sql`: adds `archive_state` (`active_r2`/`archiving`/`archived_drive`/`restoring`/`reconciliation_required`), `archive_provider`, `archive_locator`, `archive_hash`, `archived_at`, `last_verified_at`, plus an index. `status` is deliberately untouched, so archived files stay listed in the gallery and are restored on demand.
- **`GoogleDriveProvider`**: Drive v3 REST over a server-side OAuth refresh token; fails closed when credentials are absent; updates in place on retry so a re-archive never duplicates the cold object.
- **`archiveFile`/`restoreFile`**: verify-before-delete. Any post-copy failure preserves *both* copies and marks `reconciliation_required` rather than guessing. Restore is a copy-back, so the cold copy is never orphaned.
- **Worker handlers** `archive_file`/`restore_file`, and `POST /api/files/:id/archive|restore`.
