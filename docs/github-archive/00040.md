## Summary

Resolves a security vulnerability in the background worker where `POST /api/jobs/run?workspaceId=...` called `drainQueueOnce(targetWorkspaceId)`, but `dbClaimJob` at the SQL level claimed any runnable job globally using `SKIP LOCKED` without workspace filtering. While PR #38 isolated HTTP response outcomes, the worker was still claiming and executing other workspaces' jobs behind the scenes.

- **SQL Migration**: Updated `octo.claim_job` in `supabase/migrations/20261001030000_slice6_jobs_and_activity.sql` to accept `target_workspace UUID DEFAULT NULL` and filter: `AND (target_workspace IS NULL OR j.workspace_id = target_workspace)`.
- **Server DB Client**: Updated `dbClaimJob` in `src/server/db.ts` to accept `targetWorkspaceId: string | null = null` and pass it to `octo.claim_job(, , )`.
- **Queue Draining**: Updated `drainQueueOnce` in `src/server/index.ts` to pass `targetWorkspaceId ?? null` to `dbClaimJob`.
- **Schema Assertions**: Added unit assertions in `tests/test_slice6_schema.py` verifying the SQL parameter and filter.
