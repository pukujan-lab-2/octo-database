### Human-Understandable Summary
The lead developer/platform owner needs a dedicated, elevated administration surface directly inside Octo's Control Dashboard to monitor multi-tenant infrastructure health, storage tiers, and tenant workspaces without manually querying raw Postgres tables or switching context to external browser tabs.

When authenticated as the platform owner (`pujan3645@gmail.com` / `PLATFORM_OWNER_EMAIL`), the dashboard should display a distinct `👑 Platform Owner` badge and a `⚡ Platform Admin` launcher button in the AppBar. This opens an Admin Console modal providing:
1. Live platform infrastructure and storage tier status (Postgres with pgvector, Cloudflare R2 active bucket, Google Drive 5TB cold archive quota, and gravebuster host node status).
2. Direct launcher links to external cloud administration consoles (Cloudflare Zero Trust, Google Cloud Console, Supabase Studio).
3. System-wide Workspaces Registry listing all tenant workspaces with name, slug, active role, and a quick "Switch Workspace" action.

All items here are filed as a non-binding observational proposal.

### Reproducibility Steps / Evidence
1. Launch Octo web interface: navigate to `http://localhost:8091/` on gravebuster host or local dev server.
2. Sign in as the lead developer (`pujan3645@gmail.com`).
3. Observe that previously, the AppBar did not distinguish platform owner identity from standard workspace members, and inspecting cross-tenant workspace memberships or storage tiers required direct database queries or manual API calls.
4. Verify backend routes in `src/server/db.ts` and `src/server/index.ts`: platform owners require explicit global owner permissions across all workspaces (`dbGetAuthorizedWorkspaces`, `dbGetWorkspaceMembership`).
