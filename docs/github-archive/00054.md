### Priority Rating
P5 (High Architectural Impact — Cross-System Boundary Decoupling)

### Risk & Blocker Classification
Architectural Boundary Alignment & Anti-Bloat. Octo's core mandate is multi-tenant database management, PostgreSQL RLS security, Cloudflare R2 active object storage, and Google Drive 5TB cold archival. Maintaining bespoke issue logging templates and coordination workflows within Octo creates scope expansion and maintenance drag.

### Human-Understandable Summary
This observational issue records the architectural decision to decouple issue logging, 3-plane governance, and multi-agent coordination out of Octo into a dedicated upstream project: \Pukujan/observational-issue-ops\.

Octo will no longer own or customize issue triage rules or coordination protocols. Instead, Octo becomes a clean **adopter** of the unified stack:
1. **Adopter Package Manifest:** Octo will check in a single lightweight \stack-manifest.json\ that pins compatible Release Train versions of \observational-issue-ops\ (OIO), \project-continuity-modules\ (PCM 0.6.0), \content-generation-modules\ (CGM 0.5.7), and \gent-custom-setup\ (ACS 0.1.0).
2. **Private Evidence to Public Receipts:** Octo's PostgreSQL operational tables (\octo.activity\ and \octo.evidence\) will act as the private System of Record. Operational events and audits will compute cryptographic SHA-256 evidence hashes that link directly into public GitHub issue receipts (\coord:receipt\), preserving data privacy while maintaining verifiable public provenance.
3. **Template & Workflow Management:** Octo's current bespoke \.github/ISSUE_TEMPLATE/observational-issue.yml\ and \.github/workflows/issue-triage.yml\ will be managed and updated via the \observational-issue-ops\ CLI installer rather than hand-edited.

### Reproducibility / Current State
Currently, Octo maintains its own local issue template (\.github/ISSUE_TEMPLATE/observational-issue.yml\) and triage workflow (\.github/workflows/issue-triage.yml\). While functional, any updates to the 3-plane rubric, priority rules, or anti-forgery attestations must be manually ported across repositories, creating the exact silent drift measured in ACS #46.
