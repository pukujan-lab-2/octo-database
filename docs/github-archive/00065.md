## Summary

Implements the owner-approved workspace data-plane design (`docs/superpowers/specs/2026-10-01-octo-workspace-data-plane-design.md`, merged in #64), answering the owner's product questions in #61.

- **Workspace = database.** Atomic `POST /api/workspaces` (slug collision → `409 SLUG_TAKEN`, workspace-key callers refused `403`) and `DELETE /api/workspaces/:id`. Creating a workspace auto-provisions exactly one workspace key and shows the secret once.
- **Key model.** Exactly one account-wide key per principal (partial unique index `uq_api_keys_account_wide`) plus one key per workspace. Named presets (Read-only / Read-write / Ingest / Full) and a custom scope picker; revoke and expiry surfaced in the dashboard.
- **Destructive-command protection.** `principals.confirm_secret_hash`. Destructive routes fail closed: unset → `412`, key caller → `403` (API keys can never delete), wrong secret or slug mismatch → `403` / `CONFIRM_SLUG_MISMATCH`.
- **Retention / tiering.** `workspaces.retention_days` (NULL = never auto-archive) drives `runRetentionSweep`, run by `startSchedulers` so the queue drains without a manual "Run worker pass". Uploads still land in R2; Drive is cold only and restored on demand.
- **Agent API.** Real `requireScope` enforcement on activity, jobs-run, archive, restore, and keys-revoke; dead `src/api/gateway.ts` removed; in-dashboard "Using your key" panel documents the Bearer format and the full action/scope table.

Also fixes a permanent re-archive block: the archive job idempotency key was `archive:<fileId>` and the `(workspace_id, job_type, idempotency_key)` uniqueness meant a second archive cycle never enqueued. The key is now transition-cycle-scoped (`archive:<fileId>:<cycle>`).
