## Summary

- `DELETE /api/workspaces/:id` parsed its body with a bare `JSON.parse(await readBody(req))`, so an empty or non-JSON payload threw *before* `confirmGate` ran and the request returned **500** instead of the intended refusal.
- Added a tolerant `readJsonObject(req)` helper (empty/malformed → `{}`) and used it in the three workspace-data-plane routes, so each route's own validation produces its contract-shaped 400/403/412.
- Added a regression assertion to the MR-3 & MR-7 E2E: a **bodyless** key delete must be `403`, never `500`.

Found while running the required live end-to-end verification against production after promoting #58. The delete is still refused either way (fail-closed gate), so no data risk — the defect is the wrong status code and an unhandled-error log line.

Closes #66. Part of #61.
