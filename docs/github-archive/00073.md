## Summary

Updated the issue #72 research checkpoint with current primary-source documentation for the requested control-plane alternatives. It compares console workflows, project support, PostgreSQL fit, and integration effort; proposes a no-migration working default; describes native-console boundaries for PostgreSQL/pgvector, Neo4j, and DuckDB; and records the existing owner-directed reuse rule.

## Findings

- Self-hosted Supabase Studio is a single-project console. A shared project minimizes fleet operations, while one project per workspace adds provisioning and ongoing stack maintenance. Moving Octo's current runtime onto Supabase would still be a platform migration.
- pgAdmin is a specialist multi-server PostgreSQL console. DBeaver supports organized desktop connections and a Team Edition web surface. Directus, NocoDB, and Baserow focus on data workflows with different database and workspace limits; Hasura and Nhost add app/API platform capabilities; Appwrite's native PostgreSQL is documented in Appwrite Cloud.
- Keep Octo's dashboard, gallery, and operations workflows. Link to mature consoles for specialist administration instead of recreating them.
- Gravebuster is visible on Tailscale but SSH authentication is denied from this session. Production `/health` currently reports PostgreSQL and R2 connected and Google auth configured.

## Scope

Docs only. No code, deployment, provider migration, dashboard deletion, or topology change. The document is linked to issue #72 and leaves the workspace-to-database-project mapping for the owner.
