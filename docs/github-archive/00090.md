# Issue #90: Fix AuthGate/LoginPage useMe render loop (request storm) in Dyad v2

- State: closed (2026-10-04)
- Opened by Pukujan on 2026-10-03
- Original: https://github.com/Pukujan-lab/octo-database/issues/90

## Goal
Stop the request/log storm in Dyad v2 (branch `dyad-v2`, commit 362c4a4 onward). In live mode, when `GET /api/me` fails (backend on :3001 down → Vite proxy 502, or logged-out 401), `AuthGate` and `LoginPage` mount and unmount each other in an endless loop. That fires about 150 `/api/me` + `/health` requests per second.

## Root cause
- `AuthGate` renders `<Splash/>` while `useMe().isLoading`, otherwise `<LoginPage/>`.
- `LoginPage` calls `useAuth()` → `useMe()` and `useHealth()`. Each mount adds a new observer on an errored query that has no data.
- TanStack Query v5 then refetches on mount (`shouldLoadOnMount`), and the refetch resets status to `pending`. So `isLoading` flips true → Splash → LoginPage unmounts → fetch fails → LoginPage remounts → repeat.
- The fixes in 501f2a4/57aa953 (`retry:0`, staleTime, `offlineUntil` breaker, `quietExpectedRefusal` proxy listener) can't stop this:
  - Vite answers ECONNREFUSED with a 502, so `fetch` resolves and the breaker never trips.
  - Vite's own logging error handler stays attached, so the custom listener can't silence it.

## Scope
- `src/v2/data/hooks.ts`: `retryOnMount: false` on `useMe` and `useHealth`. `useMe` resolves `null` in live mode when there's no session token.
- `src/v2/components/auth/auth-gate.tsx`: show Splash only while `isLoading && !isError`.
- `src/v2/data/live.ts`: treat 502/503/504 as unreachable (set `offlineUntil`, throw).
- `vite.config.ts`: remove the ineffective `quietExpectedRefusal` listener.
- Add the review doc `docs/reviews/2026-10-03-dyad-local-review.md`.
- Out of scope: server, auth model, visual design.

## Done when
- [ ] `npm run typecheck` and `npm run build` pass.
- [ ] Headless check: live mode, backend down, ~5 s → a handful of `/api` + `/health` requests (not hundreds), and the login screen renders with the "server unreachable" notice.
- [ ] PR into `dyad-v2` links this issue.
