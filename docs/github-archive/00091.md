## Root cause
- In live mode, a failed `GET /api/me` leaves the `["me"]` query in `error` with no data. It fails when the backend on :3001 is down (the Vite proxy answers 502) or when the user is logged out (401).
- `AuthGate` shows `<Splash/>` while `isLoading`, otherwise `<LoginPage/>`. `LoginPage` calls `useAuth()` → `useMe()` and `useHealth()`.
- Each LoginPage mount adds a new observer. TanStack Query v5 `shouldLoadOnMount` refetches an errored query with no data, and `fetchState()` resets it to `pending`. So `isLoading` turns true → Splash → LoginPage unmounts → request fails → LoginPage remounts → repeat.
- The earlier fixes (501f2a4, 57aa953) couldn't stop this:
  - `retry`/`staleTime` don't affect mount-triggered loads.
  - The `offlineUntil` breaker only tripped on a thrown `fetch`, and Vite resolves with a 502.
  - Vite attaches its own logging error handler after `configure()`, so `quietExpectedRefusal` can't silence it.

## Fix
- `hooks.ts`: `retryOnMount: false` on `useMe` and `useHealth`. This is what breaks the loop. `useMe` also resolves `null` in live mode when no session token is stored, so there's no request at all when signed out.
  - `refetchOnMount: false` would not have worked: it's ignored when there's no data.
  - Guest sign-in still works because `invalidateQueries()` refetches regardless of `retryOnMount`.
- `auth-gate.tsx`: Splash only while `isLoading && !isError`.
- `live.ts`: 502/503/504 count as unreachable (sets `offlineUntil`, throws the unreachable error). This is defense-in-depth, not the fix.
- `vite.config.ts`: removed the ineffective `quietExpectedRefusal` listener and its two `configure:` lines.
- `docs/reviews/2026-10-03-dyad-local-review.md`: the full review, covering the root-cause evidence, why Dyad's attempts failed, and why v2 looks better than v1.
