## Summary
- `POST /api/keys` accepted any `workspaceId`/`scopes` from an authenticated caller. A workspace-bound or read-only token could mint an **account-wide** key, mint into **another workspace**, or grant itself **scopes it never held**. `authorizeKeyMint` now makes every API-key caller narrow-only.
- The route validates its body (typed `name`, `expiresInDays`, `scopes`, UUID `workspaceId`) instead of trusting `JSON.parse`.
- The file, share, job, and RAG routes share the same tolerant reader, so a malformed or empty body is a clean `400` (issue #66 class) rather than an unhandled `500`.
