## Summary
- An `archive_file` / `restore_file` job whose target file was deleted is no longer failed permanently with `FILE_NOT_FOUND`. The transition is moot once the file is gone, so the worker now completes it as an explicit no-op (`no-op: file <id> no longer exists`).
- `dbRetryJob` no longer refuses to requeue a failed transition job just because the file is gone, so a job stranded by an older deployment can be retried and cleared by the worker.

Together these remove an unclearable red failure in a workspace's operations view — the state observed in the production `Personal` workspace (a failed `archive_file` job for a since-deleted file that could neither be retried nor dismissed).
