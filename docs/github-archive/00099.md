## Summary
- Guest signup and Google onboarding derive the auto-provisioned workspace slug from only the first 8 hex chars of a fresh id (32 bits). `dbInsertWorkspace` ends in `ON CONFLICT (slug) DO UPDATE ... RETURNING`, so a collision returns the *victim's* workspace id and the next line (`dbInsertMembership(..., 'owner')`) grants the new signup ownership of a stranger's workspace.
- Measured rate via simulation: ~3.5 collisions per 200k signups over 20 runs (birthday expectation ~1.9) — rare but live.
- Fix: `src/lib/provisioning-slug.ts` uses the full identifier (122 bits); wired into all three producing sites (`src/server/index.ts` guest route, Google onboarding slug, and `src/auth/session.ts`). Storage keys are workspace-UUID-based (`workspaces/{workspaceId}/{fileId}/...`), so widening the slug affects only display and the delete-confirmation prompt, which already carries the slug dynamically.
