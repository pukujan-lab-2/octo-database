## Summary
- A workspace-scoped API key is bound to one workspace; ~12 routes enforce that with `keyWorkspaceMatches()` + a role cap via `roleAllows()`. Six sibling routes checked membership only, so a key minted for workspace A could act on any other workspace its principal owned.
- Fixed routes: shares **create** (`index.ts:1845`), shares **list** (`:1927`), shares **revoke** (`:1958`), job **retry** (`:2292`), RAG **ingest** (`:2376`), RAG **query** (`:2489`). Each now runs the pin and swaps the inline role comparison for the existing `roleAllows(auth, mem.role, <min>)` helper.
- On the two RAG routes, authorization now runs before the embedding-provider probe, so an unauthorized caller cannot infer provider state.
- Verified as a real defect, not theoretical: before the fix, a key bound to workspace A created a share in workspace B (201).
