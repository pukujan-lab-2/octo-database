## Summary
Two independent ways the single-process hosted runtime could exit on input it should have handled. Both are "the host must not die" fixes.

### 1. Idle pooled-client error (src/server/db.ts)
The Postgres pool had no `'error'` listener, so an idle client error (server restart, network reset, admin termination) was rethrown by Node as an uncaught exception and exited the container. Attach a handler that logs and lets the pool discard the broken client; add `connectionTimeoutMillis: 5000` so a hung dial fails instead of stalling a request.

### 2. Malformed request target (src/server/index.ts)
`new URL(req.url, base)` ran *before* the request handler's `try/catch`. An absolute-form target like `GET http://[ HTTP/1.1` throws `ERR_INVALID_URL` as an unhandled rejection and exits the process — a pre-auth remote DoS reachable by any client that can open a socket. Construct the URL inside its own guard and return a clean 400.
