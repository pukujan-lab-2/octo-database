## Summary
Two hosted-runtime routes answered `500 INTERNAL_SERVER_ERROR` with internal text for ordinary client input — neither a mutation risk, both a wrong status and a leaked message:

- `POST /api/auth/guest` parsed its body with a bare `JSON.parse`, so a malformed or `null` body reached `.displayName` and threw. It is an anonymous, bodyless-friendly endpoint, so it now reads the body with the tolerant `readJsonObject` and defaults an absent `displayName`. (This closes the one body-reading route that issue #66 recorded as out of scope.)
- `POST /api/keys` and `POST /api/workspaces/shares` added a client-supplied day/hour count to the current `Date`, so a large value overflowed the Date range and `toISOString()` threw `Invalid time value`. Both now refuse an out-of-range value with a 400 before converting.
