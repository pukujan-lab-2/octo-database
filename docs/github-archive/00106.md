## Summary
- The workspace has no name uniqueness, so re-uploading a changed file left the old record behind — after a delta run a backed-up path appeared twice, and every later run added another copy.
- The CLI now lists the workspace after a successful upload and deletes prior records whose remote path matches, so a backed-up path holds exactly one current copy.
- Delete happens *after* upload so the workspace is never left without a copy; matching by exact remote path also clears duplicates left by earlier runs.

## Details
- `supersededFileIds(remotePath, existing)` holds the pure matching decision and is unit-tested (new `describe` block, 3 cases, RED first).
- The CLI does the listing/deletion via the existing `GET /api/files` and `DELETE /api/files/:id` routes.
- Needs a token with the `delete` scope; without it uploads still succeed and prior versions are reported as `replaceFailed` rather than crashing.
