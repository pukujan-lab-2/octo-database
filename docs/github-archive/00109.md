## Summary
- Static asset serving (the built-asset branch and the SPA fallback) piped `fs.createReadStream(...).pipe(res)` with no `'error'` handler.
- The path is guarded with `existsSync`/`statSync`, but a read can still fail after the guard — the file is removed, permissions change, or the disk errors between the check and the open.
- An unhandled stream `'error'` is an **uncaught exception**: one unreadable asset crashed the entire server process, not just the request.

## Change
- New `src/server/static-file.ts` with `sendStaticFile(res, filePath, contentType)`, used by both static sites.
- On a read error it answers `500 STATIC_READ_FAILED` for that one request and keeps the process serving. It also skips writing to a response the client already destroyed (avoids turning a disconnect into a throw outside the request handler's try/catch).
