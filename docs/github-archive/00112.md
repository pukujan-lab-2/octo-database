## Summary

Makes PostgreSQL Row-Level Security a real engine-level backstop, so a workspace-scoped API key cannot reach another workspace **even if application code has a bug** — the owner's stated fear ("someone's agent ruins another project's database"). Closes the gap tracked in #111.

Today the server connects as the `postgres` superuser (which bypasses RLS unconditionally) and never sets a request identity, so the policies never fire; isolation rests entirely on hand-written predicates.

## What changed

- **Two runtime roles** (`supabase/migrations/20261001080000_slice14_key_scope_isolation.sql`): `octo_app` (non-superuser, non-owner → RLS applies) for the request path, and `octo_service` (`BYPASSRLS`) for the trusted surface (login/bootstrap, job worker, archive lifecycle, server-owned `jobs`/`activity` writes). Roles are created **without passwords**; credentials are set out-of-band.
- **The fence**: a RESTRICTIVE `tenant_scope_fence` on every tenant table, keyed on the **key's workspace scope** (GUC `request.workspace_id`), not just the principal's membership — a scoped key whose principal is legitimately a member of several workspaces is still confined to its own. The migration enables RLS on each fenced table so the policy can never be inert.
- **Per-request identity** (`src/server/db.ts`): `octo.principal_id` + `request.workspace_id` are bound `set_config(..., is_local => true)` inside each statement's transaction, so claims are discarded at COMMIT/ROLLBACK and cannot leak across pooled callers. Two pools; `withTransaction` selects by pool.
- **Request wiring** (`src/server/index.ts`): `authenticateRequest` binds the identity; every request runs inside a fresh identity holder. The retention sweep (no caller identity) reads its archive target through the trusted pool — `dbGetFile` is fenced and would silently return nothing otherwise.
- **Proof** (`scripts/verify-key-scope-fence.ts`): seeds workspaces owned by one principal (membership would permit cross-workspace access) and asserts, as `octo_app` against a live DB, that a scoped session can neither read nor write another workspace, plus GUC-leak safety.
- **CI** (`.github/workflows/gates.yml`): provisions the two roles, runs the fence proof, and runs the E2E suite **as `octo_app`** so the fence is exercised, not dormant.
