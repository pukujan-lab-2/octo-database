## Summary

Adds `octo-sync` (`npm run sync`) — a per-project sync client that reconciles one local project directory against one Octo workspace. This is piece (b) of the per-project workspace model: an agent gets a workspace-scoped key in a project's `.env` and uses this tool to keep the project's files in its own workspace, so it cannot touch another project's data.

Three explicit, on-demand commands (no daemon, no watching):

- `status [path...]` — read-only; classify every path against the baseline
- `push [path...]` — upload local new/changed files
- `pull [path...]` — download remote new/changed files

## Design

- **The workspace is canonical; the local tree is a partial working set.** Neither command ever deletes the other side — absence on either side means "not checked out here", not "delete the cloud copy". Conflicts (both sides changed) are reported and refused unless `--force` names a direction. Delete/rename propagation are out of scope.
- **Baseline-based change detection.** There is no server-side content hash, so the client records a per-path `sha256` + remote record id. A remote change is a differing record-id set (uploads always mint a new id); a local change is a sha256 mismatch. A size+mtime match reuses the recorded hash instead of re-reading.
- **State is bound to `baseUrl` + `workspaceId`** and refuses to run against a different target rather than mis-applying a baseline.
- **Safe push replacement.** Push deletes only the exact prior record ids this client exchanged (`pendingDelete` + `baseline.remoteId`), never a broad same-name sweep that could remove another writer's record.
- **Safe pull.** A remote name is validated as a safe relative path before any write; bytes are written to a temp file and `renameSync`'d over the target.

## Structure

- `src/sync/reconcile.ts` — the pure three-way planner (no filesystem, no network), mirroring `src/backup/planner.ts`.
- `scripts/octo-sync.ts` — the CLI driver, reusing `walkFiles` / `classifyLocalFile` / `classifySize` and `OctoApi`.
- `tests/unit/sync-reconcile.test.ts` — 21 tests pinning the classification matrix, action selection, path safety, and helpers.

## Config

- `.octo/config.json` (committed) carries `{ baseUrl, workspaceId }`.
- `.octo/state.json` (machine-local, gitignore it) holds the baseline.
- The token is env-only (`OCTO_TOKEN`, fallback `OCTO_MCP_TOKEN`) and never written to disk. `.octo` is ignored by the walker so config/state are never transferred.
