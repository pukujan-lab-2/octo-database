## Summary

Records the owner's decision on the per-project key's scopes: a workspace-scoped key used for sync must carry `read`, `write`, `files`, and `delete`.

`delete` is required because `push` replaces a record by delete-then-upload — a key without it can upload but never converge (the superseded record stays and the next run reports `ambiguous`). This matches the scope set `docs/backup.md` already documents for the same reason.

No behavior change: the server's default scope set stays conservative (`read, write, files`) so a key is never destructive by omission; the per-project setup requests `delete` explicitly.
