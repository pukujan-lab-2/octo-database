# Issue #124: Slice 16 — Workspace-creation daily limit (1/day, platform-owner exempt)

- State: closed (2026-10-05)
- Opened by Pukujan on 2026-10-05
- Original: https://github.com/Pukujan-lab/octo-database/issues/124
- Labels: enhancement

## Summary

After Slice 15 stamps creation with a human secret, add a second, independent guard: a principal may create at most **one workspace per day**, unless it is the platform owner. Prevents spam even from a compromised browser session.

Parent: #122

## Identity and lineage

- Parent: #122
- Depends on: Slice 15

## Observed facts

- `octo.workspaces` already records `created_by` and `created_at` (see `supabase/migrations/20261001000000_slice1_principals_workspaces_memberships.sql`), so a per-day count can be **derived** — a new counter table is not strictly required.
- `principal.isPlatformOwner` is the existing admin flag (`src/server/index.ts`).

## Proposal

*(proposal)* On `POST /api/workspaces`, after the Slice 15 stamp and before provisioning:

1. If `!auth.principal.isPlatformOwner`, count workspaces with `created_by = principal.id AND created_at >= now() - interval '1 day'`. If ≥ 1, refuse with a clear error (e.g. `WORKSPACE_DAILY_LIMIT`).
2. Platform owners are exempt (no count).
3. Surface the refusal message in the create modal.

**Open modeling question for implementation** (decide at build time, minimum sufficient change): derive the count from `octo.workspaces` rows, or record an explicit counter. Derivation reuses existing state and needs no migration; prefer it unless a concrete reason appears.

**Human-removable limit.** The owner wants a limit a human can remove manually. The natural home is the platform-owner Admin Console (#52). Do not build a new settings surface here; if #52 is not ready, the owner-exempt rule already gives the human an override, and a per-principal override can be added to #52 later.

## Acceptance criteria

- [ ] A non-owner principal creating a second workspace within 24h → refused.
- [ ] The same principal may create again after the window passes.
- [ ] The platform owner is never limited.
- [ ] The refusal is a clean 4xx with a stable error code, shown in the UI.

## Boundaries / non-goals

- No rate limiting of key minting, uploads, or other writes (owner chose workspace-creation only).
- No generalized rate-limit middleware or policy engine.

## Next action

Add the per-day count check to `POST /api/workspaces` behind the owner-exempt branch.
