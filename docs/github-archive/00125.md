# Issue #125: Slice 17 — MFA (TOTP) step-up for destructive commands (deletion)

## Summary

Add a second factor to the human confirmation gate so that even a hijacked browser session cannot delete a workspace with the secret alone. TOTP first (authenticator app), WebAuthn/passkeys later.

Parent: #122

## Identity and lineage

- Parent: #122
- Depends on: Slice 15

## Research

- **Mechanism.** TOTP via a small library (e.g. `otplib`): per-principal secret, QR enrollment, 6-digit codes. Recovery codes for lockout. WebAuthn/passkeys are the phishing-resistant follow-up, not this slice.
- **Where it plugs in.** The confirmation gate is `confirmGate` (`src/server/index.ts:598`). MFA is an **additional** condition on the same gate: human session **AND** confirmation secret **AND** valid TOTP. API-key callers remain refused before any MFA check.
- **Enrollment surface.** The dashboard's Access/Settings area already holds the confirmation-secret control (`src/main.ts:199`, `315-319`); MFA enrollment (show secret, verify a code, issue recovery codes) belongs beside it.
- **Storage.** A per-principal MFA record (secret, confirmed-at, recovery-code hashes). Store the TOTP secret encrypted/at-rest as the platform already handles comparable secrets; do not build a new secret-management system (AGENTS.md #3).

## Proposal

*(proposal)*

1. Enrollment endpoints: begin enrollment (return TOTP provisioning URI/secret once), confirm with a code, list/rotate/disable.
2. `confirmGate` (or a thin wrapper) additionally requires a valid TOTP code when the principal has MFA enabled.
3. If MFA is not yet enrolled, deletion behaves as today (secret only) — enrollment is opt-in per principal, so the slice ships without locking the owner out.
4. Apply to `DELETE /api/workspaces/:id` first.

## Acceptance criteria

- [ ] A principal with MFA enabled cannot delete a workspace with secret-only; a valid TOTP code is required.
- [ ] API-key callers remain refused regardless of MFA.
- [ ] Enrollment is reversible (disable/rotate) and cannot lock the owner out.
- [ ] Recovery path exists and is tested.

## Boundaries / non-goals

- No passkeys/WebAuthn (later slice).
- No MFA on non-destructive reads.
- No new secret-management/rotation infrastructure.

## Next action

Design the per-principal MFA record and the enrollment endpoints; wire TOTP into the delete path.
