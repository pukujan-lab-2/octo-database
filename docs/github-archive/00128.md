## Summary

- Route `POST /api/workspaces` and `POST /api/keys` through the existing `confirmGate`, so creating a workspace and minting a key now require a human session plus the confirmation secret — exactly like deletion already did.
- An API-key caller is refused outright (403); a human session with no secret gets 412 `CONFIRM_SECRET_NOT_SET`; a mismatched secret gets 403 `CONFIRM_SECRET_INVALID`. This closes the gap where an agent holding the account-wide key could create workspaces or mint itself a wider key with no human in the loop.
- The Access view and both creation modals now carry the confirmation-secret field, with a one-time "set secret" control on first use. The E2E suite arms the gate and adds assertions that an API key can never create or mint.

Closes #123.
