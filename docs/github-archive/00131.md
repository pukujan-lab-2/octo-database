## Summary

Adds a per-principal TOTP second factor to the destructive-command gate. When a principal has an authenticator enrolled, `DELETE /api/workspaces/:id` requires a current code (or a one-time recovery code) in addition to the confirmation secret. Enrollment is opt-in, so the slice ships without locking anyone out.

- `octo.principals` gains an encrypted TOTP secret, a confirmed-at stamp, and recovery-code hashes (migration `20261001100000`).
- `src/lib/mfa.ts` wraps `otplib` for TOTP and AES-256-GCM-encrypts the secret at rest, keyed from `OCTO_MFA_SECRET` via the platform's existing env mechanism.
- `confirmGate` takes `{ requireMfa, mfaCode }`; `verifyMfaCode` falls back to a single-use recovery code and fails closed on every error path.
- Enrollment / disable / rotate routes, an Access-page Security panel, and an authenticator-code field in the delete modal.
