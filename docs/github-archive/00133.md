## Summary

Slice 19 (#127): give the roadmap's named consumers a documented authority profile that is actually enforced.

- **Key classes** — `analytics` → `read`, `agent-read` → `read+files`, `program-write` → `read+write+files`. `POST /api/keys` accepts an optional `keyClass` that expands to the class's scopes at mint time. A class is a **preset over the real scopes**, never a second authorization dimension: no `key_class` column is stored, and every route is still decided by `requireScope`.
- **Enforcement hole closed** — the three share routes (create/list/revoke) had role checks but no scope checks, so a `read`-only key could mint a share. They now require `write`/`read`/`delete` respectively.
- **Inert `admin` scope removed** (#61) — accepted at mint but enforced nowhere. Cross-tenant workspace deletion is platform-owner authority gated by a human session + confirmation secret + matching slug + MFA, which no API key can satisfy, so no route ever required `admin`.
- Explicit-`scopes` minting, the default profile, the workspace-scoped fence, revoke, and the confirmation/MFA gates are all unchanged.
