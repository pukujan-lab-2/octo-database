## Summary
- The Slice 16 one-workspace-per-day limit was a check-then-act: `dbCountCreatedWorkspacesSince` ran on the service pool, then `dbCreateWorkspaceAtomic` opened a separate transaction. Concurrent create requests from one principal all saw an empty window and all succeeded (reproduced: 6 parallel requests → 6 workspaces).
- Moves the count **inside** `dbCreateWorkspaceAtomic`, serialized per principal with `pg_advisory_xact_lock(hashtext(principal_id))`, so the second create sees the first's committed row. The platform owner still passes `enforceDailyLimit: false`.
- Removes the now-dead `dbCountCreatedWorkspacesSince` and the route-level pre-check.
