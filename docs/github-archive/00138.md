# Issue #138: [SECURITY] ISS-5 — MFA recovery codes are consumable more than once (non-atomic read-modify-write)

- State: closed (2026-10-06)
- Opened by Pukujan on 2026-10-06
- Original: https://github.com/Pukujan-lab/octo-database/issues/138
- Labels: bug

From the deep security audit (`docs/security/2026-10-05-deep-security-audit-issue-log.md`, #134), ISS-5.

**Category:** authentication / MFA bypass (non-atomic state update)
**Locations:** `src/server/index.ts` `verifyMfaCode`, `src/server/db.ts` `dbSetMfaRecoveryCodes`

`verifyMfaCode` read the recovery-code hash list, checked membership, then wrote the filtered list back — a read-modify-write with no row lock or compare-and-set. Two concurrent step-up requests both read the same list, both find the code, both return true; the last write wins and the code survives. A single recovery code can authorize multiple destructive operations, breaking its documented one-time property.

**Reproduced:** 8 concurrent `dbConsumeMfaRecoveryCode` calls against the pre-fix read-modify-write returned 3 `true` (expected exactly 1).

**Fix:** consume the code in one atomic statement — `UPDATE octo.principals SET mfa_recovery_code_hashes = array_remove(..., $1) WHERE id = $2 AND $1 = ANY(mfa_recovery_code_hashes) RETURNING id` — and treat zero rows as failure.

Fixed by the linked PR.
