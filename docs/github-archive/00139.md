## Summary
- `verifyMfaCode` consumed recovery codes with a read-modify-write (read the hash list → check membership → write the filtered list back). Two concurrent step-ups both redeemed the same code; the last write won and the code survived, so one code could authorize several destructive operations.
- Replaces it with a single atomic `UPDATE ... SET mfa_recovery_code_hashes = array_remove(..., $1) WHERE id = $2 AND $1 = ANY(mfa_recovery_code_hashes) RETURNING id`; zero rows means the code was already spent.
