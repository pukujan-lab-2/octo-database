## Summary

Slice O1 of the operational layer (#140). Adds `octo.ops_events` and records a
structured failure from each place the server already catches one, then reads it
back through a fenced route.

- **Capture** — the outer 5xx handler records one `request.error` event; the
  worker's fail/exception path records `job.failed` / `job.exception`. Both are
  best-effort: a capture failure is swallowed so it can never turn a handled
  error into a crash.
- **Store** — `octo.ops_events` (nullable `workspace_id` so pre-workspace errors
  are recorded; RLS + the slice-14 RESTRICTIVE tenant fence; null-workspace rows
  readable only by the platform owner).
- **Read** — `GET /api/ops/events?workspaceId=<id>&errorCode=<code>`, gated by the
  `read` scope and workspace membership; `ops.list` added to capability discovery.

Append-only by design: the same failure recorded twice is two rows, never an
upsert. This is the evidence layer, not a new state machine — the job state
machine remains `octo.jobs`' existing CHECK enum.
