## Context

`docs/security/2026-10-05-deep-security-audit-issue-log.md` records a whole-system
audit. ISS-1/ISS-2 are tracked by #135 and ISS-5 shipped in #139. This issue is the
home for the remaining confirmed findings.

## Remaining findings

### ISS-3 — MEDIUM/HIGH — Thumbnail share route promotes a share to a principal

`GET /api/files/thumbnail` mints a principal-scoped media redirect from a share
token path, so possession of a share link yields a principal-scoped URL carrying
the creator's principal UUID in the `Location` header. Fix: keep share-scoped
media tokens share-scoped; never emit the creator's principal UUID.

### ISS-4 — HIGH — `POST /api/jobs` trusted the caller's payload — FIXED

The thumbnail handler read `storageKey`/`mimeType` from the client payload
(cross-tenant object read + derivative cache poisoning). Fixed: the handler
resolves the file record through the trusted service pool, pinned to the job's
workspace; the payload supplies only the file id. Regression test added in
`tests/integration/job-worker.test.ts`.

### ISS-6 — LOW — Hardcoded platform-owner email fallback

The platform-owner check falls back to a hardcoded email. Fix: require the
configured owner identity; do not bake an address into the source.

### ISS-7 — LOW — Dead `verifyApiKey` path

`verifyApiKey` is unreferenced. Fix: delete it, or wire it if it is meant to be
the key path.

## Out of scope

No new guardrails beyond correcting the listed defects (AGENTS.md rules 2/3/10).
