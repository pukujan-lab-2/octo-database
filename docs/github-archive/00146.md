## Summary
Closes the two HIGH findings from the 2026-10-05 deep security audit (issue #135).

- **ISS-1** — a bearer session token was a raw principal UUID. That UUID is a public identifier: it is returned to the client at login and (until ISS-3) also rode in media query strings, so anyone who observed it could act as that principal. Session tokens are now an HMAC-signed, expiring envelope (`octo_sess_<id>.<exp>.<sig>`) minted at guest/OAuth login; `authenticateRequest` accepts only that, never a bare UUID.
- **ISS-2** — the share create/list responses echoed the creator's principal id. Removed from `DbShareRow` and the two column lists; the internal resolvers keep `createdBy` for the fenced read.

New `OCTO_SESSION_SECRET` signs the tokens. Unset falls back to a per-process random secret (sessions invalidate on restart), so self-hosted deployments should set it — added to `.env.example`, `deploy/gravebuster/.env.example`, `deploy/local/.env.example`, and `docs/self-hosting.md`.
