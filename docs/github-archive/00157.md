## Summary

Two gaps in the shipped Slice 20 provisioned-database capability, both of which stop it being usable as an actual data home:

- **Reachable.** A provisioned database is meant to be connected to by an ordinary Postgres client, but `octo-db` published no port, so no client could reach one. The port is now published behind `OCTO_DB_PUBLISH_ADDR`, which defaults to loopback -- nothing is exposed until it is set. The once-returned connection string is built from `OCTO_DB_PUBLIC_HOST`, because the admin connection reaches Postgres by the compose-internal name `octo-db`, which nothing outside the stack resolves.
- **Cleaned up.** Deleting a workspace cascaded the catalog row away but left the database and its role on the cluster: untraceable through Octo, out of reach of any cascade, and leaked for good because a re-provision mints a new database under a new random name. The delete path now drops both, outside the transaction (`DROP DATABASE` cannot run inside one), and reports them in the response when the drop fails.

A published port is not covered by the host firewall -- Docker inserts its own rules ahead of it -- which is why the bind address is an explicit variable rather than a fixed value. The production host has no public IP, so the reachable set is the tailnet plus the local network.

Credential rotation is deliberately not included: nothing needs it to start using the feature, and adding it would be speculative scope.
