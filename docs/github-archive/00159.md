## Summary

Closes out slices **O3** and **O4** of issue #140 — the operational layer's exposure work. The classification views from O2 already existed; this PR makes them reachable over HTTP and gives an agent the diagnose/repair tools, **without adding any new aggregation, table, or migration**.

- **O3 — `GET /api/ops/summary?workspaceId=`**: returns the classified failures for an authorized workspace — counts by error code, by job type and day, and the jobs needing attention. It reads the O2 views through the fenced `query()` on the app pool, so the views' `security_invoker` semantics apply the caller's own RLS context. A plain definer view would have leaked every workspace's rows.
- **O4 — MCP diagnose/repair tools**: `get_ops_summary`, `list_ops_events`, and `retry_job`. The first two are read-scoped diagnosis; `retry_job` is the repair action and is refused server-side without write scope and an owner/admin role. The adapter stays a thin client — it forwards and reports the API's decision, including a refusal as a tool error.
- `ops.summary` joins the capability surface.

No autonomous healer and no repair-policy table: per the issue's own planner pass, auto-heal already ships via lease reclaim + exponential backoff + the existing retry route.
