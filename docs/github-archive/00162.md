### Human-Understandable Summary

While migrating the **design-bakery** site onto the owner's gravebuster host, a coding agent proposed — as its *recommended* option — giving design-bakery its **own self-hosted Postgres container** ("Dedicated design-bakery-db", a separate `postgres:16` service on its own volume), framed as giving the project *independence* from Octo. When the owner objected, the agent's fallback was still its own database: a Postgres container **co-located on the same host as Octo**, as a peer to Octo's own Postgres. At no point did the agent read or attempt to use **Octo's managed provisioned-database layer** — a real, independently connectable Postgres per workspace, with its own scoped role and pgvector enabled (Slice 20, #153), exposed as the MCP tool `provision_database` and `POST /api/workspaces/<id>/database`.

**This is three failures, not one:**

1. **Recommended a self-hosted Postgres outside Octo** — "for independence." The exact anti-pattern Octo exists to prevent.
2. **Fell back to a co-located Postgres** rather than Octo's database — still the agent running its own datastore, just on Octo's host.
3. **Never read or tried Octo's managed database layer**, despite having Octo's repo available and having already read `octo.workspaces`, `octo.documents`, and the `octo_live_ws_*` key. The capability the agent should have used was live on `main` the whole time.

Root cause: Octo's managed data layer was documented only inside Octo's own repository. From the design-bakery workspace there was **no signal at all** that Octo is the designated data layer, and nothing required the agent to check. "Host a database" is the default instinct for a coding agent; absent a forcing signal, the default won.

The owner caught it before anything was built: no container was created, no data moved, no design-bakery database provisioned.

### Resolution

The capability was never the gap; **discoverability and a forcing signal** were. Fixed in Octo:

- **`docs/consuming-octo.md`** — canonical agent-facing guide: Octo is the data layer; do not self-host a database (not for independence, not co-located); the narrow, evidence-based exception; the exact provision → connect → store-string path; and a copy-paste boot block for an adopter's `AGENTS.md`.
- **`README.md`** — a pointer to that guide from Octo's front door.
- The boot block is the piece that would have prevented this incident: it gives an adopting workspace an in-workspace signal without the agent needing to read Octo's repo first.
