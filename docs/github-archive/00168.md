## Summary

Slice B of the FalkorDB plan on #12: `octo-api` can talk to the graph engine when configured, and reports a clear not-configured state when it is not.

- New `src/graph/falkordb-client.ts`: the single grep-able boundary that talks to FalkorDB.
- **Isolation lives here, not in the engine.** FalkorDB inherits none of the `octo.*` RLS fence, so:
  - the graph name is derived from an authenticated workspace UUID (`graphNameForWorkspace`) and **validated as a UUID** before use — no caller passes a graph name, so no request body can name a graph;
  - only the read-only path (`GRAPH.RO_QUERY`) is exposed, so a mediated call cannot write.
- `loadGraphConfigFromEnv()` returns `null` when `OCTO_GRAPH_URL` is unset, mirroring the embedding provider, so the graph surface fails to a clear state rather than half-wiring.
- Lazy connect with retry-on-failure (a transient engine outage does not poison the client), plus query and connect timeouts so a runaway read cannot pin a request.
- Adds the `falkordb` dependency (6.8.0).
