## Deploy notes

- **The live database has already been baselined.** `octo-db` on gravebuster was created 2026-10-01 by an init script that applied migrations *without recording them*, so `octo.schema_migrations` did not exist and `migrate.sh` would have aborted the deploy on `policy "principals_select_own" already exists`. On 2026-10-06 the tracking table was created and the 13 migrations the database already had were recorded (no migration SQL run, no data touched). Backup first: `~/octo-db-backup-pre-baseline-20261006T133207Z.sql.gz`. **This deploy will therefore apply exactly one migration — `20261001130000_provisioned_databases.sql` — and nothing else.**
- `deploy.sh` applies migrations before starting the API, so the Slice 20 migration lands ahead of the code that needs it.
- The production `.env` already has `OCTO_ADMIN_URL` (derived in place from `DATABASE_URL`), `OCTO_DB_PUBLIC_HOST`, and `OCTO_DB_PUBLIC_PORT`. `OCTO_DB_PUBLISH_ADDR` is intentionally unset, so the Postgres port stays on loopback.
- The workspace-database port becomes reachable over the tailnet only after `tailscale serve --bg --tcp 5432 tcp://127.0.0.1:5432` is run on the host. Until then provisioning works and connection strings are returned, but clients cannot yet connect. Nothing is exposed to the public internet or the local network.
- `autodeploy.sh` polls `origin/production` and will deploy on merge.
