## Problem

`deploy.sh` step 4 runs the migration runner directly:

```
"$SCRIPT_DIR/migrate.sh"
```

but `migrate.sh` was committed mode `100644`, while every sibling script (`deploy.sh`, `autodeploy.sh`, `rollback.sh`) is `100755`. On a host with `core.fileMode=true` the file checks out non-executable, so the deploy fails with `Permission denied` — **after** the database has been recreated and the images built, but before the container swap.

This is why it was never caught: the `gates` workflow invokes it as `bash deploy/gravebuster/migrate.sh`, which ignores the executable bit.

## Observed

On the `6c26a94` promotion to production:

```
4. Applying database migrations...
./deploy.sh: line 53: /home/yoav/apps/octo/deploy/gravebuster/migrate.sh: Permission denied
```

`chmod +x migrate.sh` then re-running `deploy.sh` completed the promotion.

## Change

Mode change only, `100644` → `100755`. No content change.
