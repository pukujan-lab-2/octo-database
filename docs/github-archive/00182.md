## Summary

- An existing API key's allowances can be changed after mint: `PATCH /api/keys/:id` replaces `read`, `write`, `files`, and `delete`. The secret, workspace binding, and capped role do not change.
- A human session confirms with the same one-time code used to mint a key, so an API key cannot widen itself. An empty list or an unknown name (including a capability such as `publish`) is rejected before the code is consumed.
- The Access page shows those four allowances on create and as a row under each key. `write` covers publish and unpublish. `delete` covers removing the private file, and that call still needs an admin role on the key.
