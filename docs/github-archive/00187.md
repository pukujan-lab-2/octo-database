## Hosting convention: move the gravebuster deploy to `/srv/octo-database` and decide the tailnet `:5432` exposure (proposal)

**Status: proposal. Nothing has been moved, and this issue authorizes no server change by
itself.**

### Why

The host `gravebuster` now runs ~50 Docker containers across ~15 projects, each deployed a
different way: different parent directories, different port conventions, and some publishing
on the LAN or the private mesh instead of loopback. The operator's words: *"lots of https host
flying everywhere."* The fix is a small number of rules applied consistently.

### The standard

**One project = one directory = one compose file.**

```
/srv/<project>/
  app/                      # the repository checkout
  docker-compose.yml        # top-level `name: <project>` pinned
  .env                      # chmod 600, gitignored
  .env.example              # committed
  PROJECT.json
  pg/  data/  ...
```

- **Exposure — loopback by default.** Every published port binds `127.0.0.1`. Never
  `0.0.0.0`, never the mesh IP. (Docker's default publish goes to `0.0.0.0` and **bypasses
  `ufw`**.)
- **Ingress — exactly two paths.** Public via the single Cloudflare tunnel; tailnet via
  `tailscale serve`. Nothing else.

### Where this project is now (observed 2026-10-07, read-only)

| Fact | Value |
| --- | --- |
| Deploy path | `~/apps/octo/deploy/gravebuster` |
| Compose project label | `octo` |
| Services (4) | `api`, `db`, `graph`, `web` |
| Live binds | `127.0.0.1:8091` (web) ✅ loopback; `5432` (db) |
| Public hostname | `octodb.design-bakery.com` |
| **Tailnet** | **`tcp://…:5432` serve forward → `127.0.0.1:5432`** (live) ⚠️ |
| Repo dirtiness | clean (branch `production`) ✅ |
| Related issues | #43 (closed), #72 (control-plane research) |

**Deviations**

- **`octo-db` is exposed on the tailnet at `:5432`.** Whether that is deliberate (a remote
  client depends on it) or leftover is **not established**. A tailnet-exposed database is a
  first-class finding: the tailnet is a shared trust domain, and a proxy entry that keeps
  answering after its backend changes is exactly the drift this convention exists to stop.
- **12 unused image tags** on the host for this project.
- **No `PROJECT.json`.**
- **Deploy path is under `~/apps/`, not `/srv/`.**

### Target

Move the deploy root to `/srv/octo-database/` (repo at `app/`); keep the loopback binds; and
**decide the tailnet database exposure** — one of two dispositions:

- **Keep it, deliberately** — record it with the consumer that needs it, so it stops looking
  like an accident; or
- **Retire it** — reset the `tailscale serve` entry for `:5432` and reach the database only
  through the app or an explicit tunnel. Do not reset before the consumer is identified.

| Service | Bind | Ingress |
| --- | --- | --- |
| `web` | `127.0.0.1:8091` | Cloudflare tunnel over `study-os_edge` |
| `api` | internal only | reached by `web` |
| `graph` | internal only | graph projection; not published |
| `db` | `127.0.0.1:5432` | **tailnet `:5432` forward — decide** |

**The exact changes:**

1. `deploy/gravebuster/docker-compose.yml` — pin `name: octo-database` (the host label is
   currently the generic `octo`). Keep both loopback binds.
2. Add `PROJECT.json` and a committed `.env.example`.
3. Move the deploy root `~/apps/octo/deploy/gravebuster` → `/srv/octo-database/`, with the
   repo checkout at `app/`.
4. Decide the tailnet `:5432` entry: keep-with-a-recorded-consumer, or retire. Record which.

### Before any move

Re-run the probes this target was built on — `docker ps` with ports, `ss -tlnp`,
`tailscale serve status`, and `docker inspect` on the running container. This target was
written against a **2026-10-07** snapshot; if the host has drifted, the target is stale and
moving on it is the failure this whole exercise exists to prevent.

### Definition of done (read-only)

```bash
docker compose -p octo-database config >/dev/null
docker ps --format '{{.Names}}\t{{.Ports}}' | grep -i octo
ss -tlnp | grep -E ':(8091|5432)\b'              # loopback only
tailscale serve status                            # :5432 either recorded-kept or absent
curl -sI https://octodb.design-bakery.com | head -1
```

### Guardrails

1. **Do not move the live deployment from this issue alone.** Cut over only with explicit
   operator direction naming the host.
2. **Identify the consumer of `tcp://…:5432` before touching the serve entry.** "Unknown
   purpose" means identify, not delete.
3. **Pin `name: octo-database`** before the move (the host label is currently `octo`).
4. **Do not delete the old directory** as part of the move.
5. **Prune the 12 unused image tags separately**, on explicit direction — that is a server
   change, not part of the move.
6. **No secrets** in the compose file or this issue.
