## Summary

Slice 9 (#11) shipped the epistemic schema and its two bitemporal SQL functions, but **no application path ever touched the tables** — there was no way to write a claim, belief, or evidence row, and no way to read one back. The tables were schema-only, so nothing downstream (the #12 graph projection) could ever have anything to project. This adds the missing record/query API.

- **`POST /api/epistemic/record`** (write scope, operator+) appends one record: `entity`, `perspective`, `evidence`, `claim`, `belief`, `claim_relation`, or `claim_evidence`. Recording a claim with `supersedesClaimId` writes the `SUPERSEDES` relation and closes the older claim's recorded-time interval **in the same transaction** — history is appended to, never rewritten.
- **`GET /api/epistemic/claims-as-of`** — with current knowledge, which claims do we now consider valid at a world instant, with provenance.
- **`GET /api/epistemic/belief-as-of`** — what did perspective P believe about a claim at an instant, citing the evidence linked to that claim.

Writes run on the fenced `octo_app` pool, so the RLS operator-insert policy and the tenant fence are the real authorization gate; this code adds no policy of its own. Also adds the three capability descriptors, three MCP tools (`record_epistemic`, `query_claims_as_of`, `query_belief_as_of`), and an e2e oracle.
