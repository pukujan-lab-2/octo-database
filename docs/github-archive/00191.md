## Summary

The projector MERGEs and MATCHes on each node's `id`, and FalkorDB does **not** index a property on MERGE (verified against the engine: `MERGE (c:Claim {id: ...})` creates no index). So every MERGE scanned its whole label, making a rebuild **quadratic** in the workspace's row count. Issue #12 lists "Neo4j indexes needed by queries" in scope.

Create the index for each of the five node labels on the fresh graph, right after the destroy and before any node write. A rebuild always starts from a deleted graph, so the indexes never collide with an existing one — FalkorDB *errors* on a duplicate `CREATE INDEX` rather than ignoring it, which is why this must run on a clean graph.

Verified against a live `falkordb/falkordb-server:6.0.1`: after a projection, `CALL db.indexes()` reports all five (`Entity`, `Claim`, `Evidence`, `Perspective`, `Belief`) `OPERATIONAL` on `id`.
