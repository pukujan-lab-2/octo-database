## Human-Understandable Summary
A logged-in human workspace owner reported being unable to find a **Delete Workspace** button. A later UI transcription confirmed the action **does** exist, but only at the bottom of the **Access** page, after long machine-key, shared-content and security sections. In an account with numerous keys, the destructive lifecycle control is easy to miss.

This is an **information-architecture and discoverability observation**, **not** a claim that the delete API or the button is absent.

## Reproducibility Steps / Evidence
1. Sign into Octo as an owner with multiple keys.
2. Select a workspace and visit **Overview**, **Files**, **Gallery**, **Operations** and **Access**.
3. Observe that **Delete Workspace** is not exposed alongside the workspace picker, name, or overview.
4. In **Access**, scroll past the API-key inventory, shares, and two-factor authentication section.
5. Finally find **WORKSPACE → Delete Workspace** at the very bottom.
6. Source confirms button and handlers: `src/main.ts:279-288`, `src/main.ts:220-223`, `src/main.ts:427`, `src/main.ts:495-498`.
7. E2E test confirms the documented route: `tests/e2e/workspace-lifecycle.spec.ts:127-145`.

## Observed Consequence and Workaround
- User initially believed human workspace deletion was unavailable.
- Workaround: select workspace → **Access** → scroll to bottom → **Workspace** → **Delete Workspace**.
- No actual inability to delete was reproduced.

## Non-Binding Proposed Next Actions
- [ ] Surface **Manage workspace** near the workspace picker/overview, linking to settings and the existing destructive action.
- [ ] Consider a distinct workspace settings area instead of placing lifecycle management after unrelated account-wide key listings.
- [ ] Preserve current owner-only, typed slug, confirmation, MFA (when enrolled), and active-archive safety gates.
- [ ] Add a UI discoverability test or clearly documented path, including long key inventories and narrow/mobile screens.
