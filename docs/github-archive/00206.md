## What

Adds an OAuth 2.1 authorization server alongside `/mcp`, so a hosted MCP client such as ChatGPT can connect. ChatGPT's custom connectors offer only OAuth or no authentication — there is no bearer field — so `/mcp` was unreachable from one.

This also retires `/mcp/<key>`. A long-lived Octo key does not belong in a URL; `/mcp/<key>` now answers 404.

## Surface

| Route | Purpose |
| --- | --- |
| `/.well-known/oauth-protected-resource` | RFC 9728 metadata; the `WWW-Authenticate` on `/mcp`'s 401 points here |
| `/.well-known/oauth-authorization-server` | RFC 8414 discovery |
| `POST /oauth/register` | RFC 7591 dynamic client registration |
| `GET \| POST /oauth/authorize` | authorization-code + PKCE (S256) |
| `POST /oauth/token` | code exchange and refresh rotation |

## Authorization properties

- **PKCE S256 mandatory**, clients public. A `client_id` that is an https URL is resolved as a Client ID Metadata Document, taking redirect URIs from the document rather than the query string.
- **Stateless HMAC JWT access tokens**, header pinned to HS256 so no algorithm can be negotiated. Claims: `iss`/`sub`/`aud`/`scope`/`workspace_id`.
- **Audience-bound**: a token minted for one resource is refused at another.
- **Workspace-bound**: the workspace claim binds the RLS fence, so an OAuth client reaches exactly the workspace its user consented to and no further. Consent is checked against the principal's real workspace list, so a forged `workspace_id` cannot mint a code.
- **Read-only by construction**: only `read` and `files` are ever minted, so a connector cannot write even if it asks.
- **Refresh rotation**; replaying a rotated token revokes the whole family. Expiry and single-use claims are decided in SQL, not by comparing a `timestamptz` to a JS date string (that comparison silently never matches).
- **The session token never rides in a URL.** A connector opening `/oauth/authorize` cannot carry the dashboard's localStorage session, so the browser bounces through the normal login and is handed back as a short-lived HttpOnly cookie. The bounce target is pinned to this origin's authorize path, so a crafted link cannot turn the dashboard into an open redirect.

Existing bearer-key auth on `/mcp` is unchanged.

## Schema

Three tables (`oauth_clients`, `oauth_auth_codes`, `oauth_refresh_tokens`) hold server-owned credential rows on the trusted path and carry no RLS policy. The migration REVOKEs the DML that this schema's `ALTER DEFAULT PRIVILEGES` would otherwise hand the fenced request role.
