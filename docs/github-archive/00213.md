## Summary

The `octo-web` image build fails on `npm --prefix frontend ci`:

```
npm error ERESOLVE could not resolve
Dockerfile.web:9 RUN npm ci && npm --prefix frontend ci  exit code: 1
```

The frontend resolves peers with `legacy-peer-deps=true`, set in `frontend/.npmrc` — but the builder stage only copied `frontend/package.json` and `frontend/package-lock.json`, so the setting never reached the image and the install resolved peers strictly.

This broke the production deploy of #212: the poller detected the new `origin/production` SHA, the build failed at this step, and it auto-rolled back to the previous image. `gates` does not build the Docker image, so CI could not catch it.

## Test plan

- `npm --prefix frontend config get legacy-peer-deps` → `true` (proves `--prefix` reads `frontend/.npmrc`; there is no such setting in any user-level `.npmrc`)
- `docker build` of `deploy/gravebuster/Dockerfile.web` on the Mac host with this change
- After merge + promotion: the deploy's step 1 (`Building container images`) completes and the stack swaps to the new image
