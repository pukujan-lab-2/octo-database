## Summary

`deploy/gravebuster/.env.example` documented `CLOUDFLARE_R2_*` variable names, but the code does not read any of them:

- `src/storage/r2-client.ts` `loadR2ConfigFromEnv` reads `R2_ENDPOINT`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, and `OCTO_R2_BUCKET`.
- `region` is hardcoded to `'auto'`, so `CLOUDFLARE_R2_REGION` was never read either.

A repo-wide search confirms `CLOUDFLARE_R2_*` appeared **only** in this example file — nothing in the code reads them. Configuring a deployment from the example therefore produced `MISSING_R2_CREDENTIALS`, left `r2Provider` null, and silently kept the local storage backend — which is exactly why R2 was never actually wired on the live host despite the example claiming R2 was the default.

This points the example at the names the code reads, drops the never-read `CLOUDFLARE_R2_REGION`, and notes that `OCTO_STORAGE_BACKEND=local` ignores the block entirely.

Doc-only change; no runtime code touched.
