## Summary
- A workspace created through `POST /api/workspaces` now auto-provisions its own PostgreSQL database, so the workspace is immediately usable without the second, separately authorized provisioning call (which a workspace-scoped key cannot make). The 201 response reports `databaseProvisioned`.
- Best effort by design: the workspace is the durable act; a provisioning failure leaves it intact with the manual `POST /api/workspaces/:id/database` route as the retry. Guests are unaffected — their sandbox is not created through this path, so existing fail-closed tests hold.
- Capability/MCP tool descriptions and `docs/consuming-octo.md` updated to match reality (the database already exists; the explicit route is for workspaces that predate auto-provision).
- New E2E: the flag matches reality in both directions — provisioned → `SELECT 1` works; not provisioned → 404 `DATABASE_NOT_PROVISIONED`.
- Also adds an AGENTS.md test-data hygiene rule: a run removes the guest accounts and workspaces it created instead of letting them accumulate.
