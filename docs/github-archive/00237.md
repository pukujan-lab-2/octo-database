### The structural verifier (the actual oracle)

A test suite only exercises the paths it covers — a dropped block or a mangled body in an uncovered route sails through green. So the refactor is proved by an AST-level oracle instead:

1. Every top-level declaration in `HEAD:src/server/index.ts` must appear in exactly one output module, whitespace-normalized and body-identical.
2. Every route branch (0..55) must be present in the new tree, in order, unaltered.
3. The retained `handleRequest` preamble and outer catch must appear verbatim.

It caught a genuine dropped route that `tsc`, `lint:imports`, and the whole test suite would **not** have: the OAuth 2.1 delegation branch (index 1) had no home in the first pass. It is now wired into `ROUTES` as position 1, delegating to the pre-existing `src/server/oauth.ts`.

The `jobs` (37,38,42,43) and `ops` (39,40,41) families are dispatched adjacently — they are path/method-disjoint, so consolidating their order is behavior-preserving; the verifier's order check is therefore a permutation check over the branch set, not a strict sequence check.
