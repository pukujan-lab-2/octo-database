## Summary

Slice 8 gave Octo RAG **ingest** and semantic **query**, but no way to manage what was indexed — an agent (or human) that ingested the wrong thing had no way to find it again or remove it. This adds the document-lifecycle surface:

- `GET  /api/rag/documents?workspaceId=<id>` — list documents with version/chunk counts
- `GET  /api/rag/documents/<id>?workspaceId=<id>` — read one document and its immutable versions
- `POST /api/rag/documents/<id>/rename` — rename the title (metadata-only)
- `DELETE /api/rag/documents/<id>?workspaceId=<id>` — delete a document and its derived rows

Plus the capability descriptors (`rag.ingest/list/get/rename/delete`), four MCP tools (`list_documents`, `get_document`, `rename_document`, `delete_document`), and the one migration adding the `documents_update_operator` / `documents_delete_owner_admin` row-security policies the new verbs need.

## Design notes

- **Rename is metadata-only.** Versions are content-hashed and immutable, so changing the text stays a re-ingest (a new version), never an in-place rewrite.
- **Delete is one row delete.** `ON DELETE CASCADE` removes versions, then chunks and embeddings. RI actions bypass row security, so only `octo.documents` needs the DELETE policy.
- **Authority mirrors the file routes:** read for list/get, write + operator for rename, delete + owner/admin for delete. A workspace-scoped key is still fenced to its own workspace.
