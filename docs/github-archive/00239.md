## Summary

Running the deploy by hand over ssh failed with `docker: command not found`:

```
$ ssh mac '~/apps/octo/deploy/gravebuster/autodeploy.sh'
.../autodeploy.sh: line 40: docker: command not found
```

A non-login ssh shell gets the minimal PATH `/usr/bin:/bin:/usr/sbin:/sbin`, but Docker Desktop installs its CLI at `/usr/local/bin/docker`. The launchd plist sets `PATH=/usr/local/bin:...` for the timer, so the **scheduled** deploy works while a **manual** run does not.

Verified on the host:

```
$ env -i PATH=/usr/bin:/bin:/usr/sbin:/sbin bash -c 'command -v docker || echo MISSING'
MISSING
$ env -i PATH=/usr/bin:/bin:/usr/sbin:/sbin bash -c 'export PATH=/usr/local/bin:/opt/homebrew/bin:$PATH; docker --version'
Docker version 29.4.1, build 055a478
```

## Fix

Prepend `/usr/local/bin` and `/opt/homebrew/bin` to `PATH` in every script that shells out to `docker`: `deploy.sh`, `autodeploy.sh`, `rollback.sh`, `migrate.sh`, `backup.sh`, `tunnel.sh`. `bash -n` clean on all six.
