## Affected

Whoever runs the deploy by hand on the live host (`~/apps/octo/deploy/gravebuster/{autodeploy,deploy}.sh`, `rollback.sh`, `migrate.sh`, and the `deploy/mac/{backup,tunnel}.sh` helpers) — every operator session that is not the launchd timer. The scheduled autodeploy is unaffected because its launchd plist sets `PATH=/usr/local/bin:...` explicitly.

## Observed consequence

A non-login ssh shell gets the minimal PATH `/usr/bin:/bin:/usr/sbin:/sbin`; Docker Desktop installs its CLI at `/usr/local/bin/docker`. Manual run:

```
$ ssh mac '~/apps/octo/deploy/gravebuster/autodeploy.sh'
.../autodeploy.sh: line 40: docker: command not found
```

Reproduced on the host 2026-10-13:

```
$ env -i PATH=/usr/bin:/bin:/usr/sbin:/sbin bash -c 'command -v docker || echo MISSING'
MISSING
```

**Workaround:** rely on the scheduled autodeploy, or `export PATH=/usr/local/bin:$PATH` before running. Fix in flight: PR #239 prepends the Docker locations in all six scripts.

## Evidence confidence

confirmed (directly reproduced on the live host; `docker --version` 29.4.1 resolves after the PATH export)

## Impact if unresolved

low — the scheduled deploy path works; only ad-hoc manual deploys fail, and the failure is immediate and self-explanatory (not a silent wrong deploy).

## Likelihood

observed (occurred when the deploy was run manually; will recur every manual run)

## Exposure

intermittent-production — only during manual deploy operations; duration: since the deploy scripts were introduced (Docker Desktop CLI at /usr/local/bin is the standard install location on this host).

## Recoverability

documented-recovery — scheduled deploy, or export PATH manually; no state is corrupted by the failed run (`set -euo pipefail` aborts before any container change).

## Risk if unresolved

Manual deploy stays broken, so any incident response that needs an immediate manual deploy (e.g. while the timer is stopped or a hotfix must skip the poll interval) hits the same failure under time pressure.

## Risk introduced by the proposed change

Minimal: prepending two standard directories to PATH can only shadow an existing binary if one of those directories contained a different `docker`, which they do not on this host (`/opt/homebrew/bin` does not exist).

## Release relevance

None — the running service is unaffected; this concerns operator tooling only.
