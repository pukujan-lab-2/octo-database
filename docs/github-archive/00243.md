# Issue #243: readBody corrupts multi-byte UTF-8 split across request chunks

- State: open
- Opened by Pukujan on 2026-10-15
- Original: https://github.com/Pukujan-lab/octo-database/issues/243

## Problem
`readBody` in `src/server/http.ts` builds the request body with `body += chunk`. Each Buffer chunk is decoded to a string separately, so a multi-byte UTF-8 character that falls across a network chunk boundary gets replaced with U+FFFD and the stored data is corrupted.

## Observed
On 2026-10-14, while importing the legal-graph-rag citation snapshot, 12 rows containing "§" were stored corrupted. The post-import readback check caught it, and the rows were wiped and reloaded. The importer in Pukujan/legal-graphrag-starter (PR #17) now sends ASCII-escaped JSON as a workaround.

## Impact
This likely affects any request with non-ASCII text in a large enough body, including SQL writes and RAG document ingest.

## Suggested fix
Collect the raw Buffers and decode once at the end: `const chunks = []; req.on('data', c => chunks.push(c)); ... Buffer.concat(chunks).toString('utf8')`. Alternatively, call `req.setEncoding('utf8')`, which uses a StringDecoder. Add a test that sends a body with a multi-byte character split across two chunks.
