## Why

Octo's RAG embedding lane pointed at a paid remote provider. That key hit its spending cap, so `POST /api/rag/documents` and `POST /api/rag/query` started returning `403 Key limit exceeded` — semantic search was down.

This moves embeddings to a **local, keyless Ollama model** (`qwen3-embedding:0.6b`) and narrows the vector width from **1536 → 1024**.

## The schema conflict this resolves

Slice 8 fixed `octo.embeddings.embedding` at `vector(1536)` and held that "a re-embed under a new config inserts a new `embedding_configs` row rather than mutating the old one." That rule cannot hold when the **dimension itself** changes: the column is fixed-width, so a 1536 and a 1024 vector cannot coexist in it, and a config row describing a 1536 model could never be satisfied again.

So the migration discards the **derived** index and rebuilds it. Only derived rows go — chunks, embeddings, and the config rows describing them. `octo.files` (the bytes), `octo.documents`, and `octo.document_versions.extracted_text` are untouched, and `scripts/reembed-rag.ts` rebuilds the index from `extracted_text`, so **no source file has to be re-uploaded**.

## Changes

- **`db/migrations/20261016120000_rag_local_embeddings_1024.sql`** — delete derived rows, narrow the column to `vector(1024)`, recreate the HNSW index and `match_chunks`, re-issue the `EXECUTE` grant. The deletes must precede the `ALTER`: pgvector's implicit `vector → vector` cast *is* the typmod coercion and rejects a 1536-dim value.
- **`src/rag/embeddings.ts`** — a provider now counts as configured when a key **or** a base URL is set, so a keyless local server works (previously a missing key was indistinguishable from "no provider"). The `Authorization` header is omitted when no key is present. Defaults now name Ollama and 1024.
- **`scripts/reembed-rag.ts`** — one-off backfill. Per-version and transactional (a crash cannot leave a half-indexed version), idempotent, runs on the service pool because a backfill has no caller principal and the app pool is fenced by request identity.
- **`src/routes/rag.ts`** — the two 503 messages now name `OCTO_EMBEDDING_BASE_URL` / `OCTO_EMBEDDING_MODEL` instead of an API key that is no longer required.
- Unit test dims, both `.env.example` files, and a `reembed` npm script.

## Verification

Against `pgvector/pgvector:pg16` (the production image), through the real `migrate.sh`:

- all **20** migrations apply in order; a second run applies **0** (idempotence, the check `gates` performs)
- column reports `vector(1024)`; `match_chunks` recreated with the right signature and grant intact
- a 1024-dim vector inserts and `match_chunks` returns it with similarity 1.0; a **1536-dim insert is rejected** by the new column
- proven that `ALTER` before `DELETE` fails with `expected 1024 dimensions, not 1536`, confirming the ordering is required rather than incidental

Also: `npm run typecheck`, `npm run lint:imports`, and `npm test` (312 tests) all pass.
