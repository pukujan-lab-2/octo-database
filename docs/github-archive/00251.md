# Issue #251: Keys dashboard: batch import, honest confirmation gate, filter, and reachable nav

- State: closed (2026-10-30)
- Opened by Pukujan on 2026-10-17
- Original: https://github.com/Pukujan-lab/octo-database/issues/251

## Problem

The Keys dashboard (view `vault`, #247) is the owner's password-manager cabinet. The owner is about to bulk-import dozens of credentials into an account cabinet that already holds 171 items, and reported: "the key dashboard is very hard and not properly ux especially with the confirmation code".

Concretely:

1. **The gate reads like documentation.** `ConfirmGate` renders inside the intro paragraph of the Cabinet panel, so it does not look like a field the user must fill before each action.
2. **One typed code per action.** The confirmation code is single-use and 10-minute-lived. Every save, remove, revoke, mint and health check consumes it, clears the field and re-issues a code — so importing N keys costs N fetch-and-retype cycles.
3. **No expiry feedback, raw errors.** The 10-minute TTL is invisible and the server's machine code (`CONFIRM_CODE_INVALID: …`) surfaces verbatim.
4. **171 rows, no filter.** The cabinets render a flat list with no search and a tall row layout.
5. **"Keys" can be off-screen.** On narrow windows the nav is a horizontal `overflow-x-auto` strip and Keys is the sixth item, with no visible affordance that it scrolls.

## Proposed fix (frontend UX + one minimal server route; gate semantics unchanged)

- Move the gate out of the intro paragraph into its own titled block, show "expires in Xm" from the `expiresAt` the server already returns, mark it used and auto-refresh after each consumed code, autofocus the typed field, and map `CONFIRM_CODE_INVALID` / `CONFIRM_SECRET_INVALID` to plain sentences.
- **Bulk import (the priority):** a "Paste many" textarea in each cabinet, one `LABEL=secret` per line, submitted through one new `POST /api/vault/items/bulk` route that validates every line first, then calls `confirmGate` **once** and inserts the batch in a single transaction. Atomic: a malformed line rejects the whole paste and consumes no code.
- Per-cabinet search over label + description, and a compact single-line row layout.
- Wrap the mobile nav instead of scrolling it, so Keys is always visible.

**Considered and deferred:** a "stay unlocked this session" toggle that sends the stored confirmation secret. The bulk route removes the repeated-typing pain for the actual workflow; an in-memory plaintext-secret holder adds surface for no remaining benefit. Revisit if single-action typing still hurts.

## Scope

- No change to `src/server/confirm.ts`, the challenge store, or any other gated route.
- Existing `data-testid`s (`view-vault`, `confirm-code-value`, `confirm-code`, `mfa-code`, `one-time-secret`) stay, because `tests/e2e/vault-grant-holdout.spec.ts` drives them.
- Bulk kind is one selector per paste (default `token`), not per line. Say so if per-line kinds are needed.
- Cap: 200 lines per paste.

## Acceptance

- A 3-line paste creates 3 items with one typed code.
- One malformed line → 400 naming the line, and zero items inserted.
- A >200-line paste → 400 and no code consumed.
- Filtering by a substring of label or description narrows both cabinets.
- At 390px width the Keys nav item is visible without horizontal scrolling.
- `npm run typecheck`, `npm run lint:imports`, `npm test`, and the Playwright e2e suite pass.
