## Summary

The Keys dashboard cost one fetch-and-retype cycle per key. This makes the gate honest and adds a one-code batch import, so a 200-line paste is one gated action instead of 200.

- **Gate**: moved out of the intro paragraph into its own panel; shows `expires in Xm` from the `expiresAt` `/api/me/confirm-challenge` already returns; marks the code used and auto-refreshes after each save; autofocuses the typed field; maps `CONFIRM_CODE_INVALID` / `CONFIRM_SECRET_INVALID` / `BULK_LINES` / `BULK_TOO_LARGE` to plain sentences.
- **Bulk import**: a "Paste many" textarea per cabinet, one `LABEL=secret` line per key. New `POST /api/vault/items/bulk` parses and validates every line **before** the gate, calls `confirmGate` once, and inserts the batch in one transaction. A malformed line returns 400 naming the line and inserts nothing, consuming no code. Cap: 200 lines. Kind is one selector per paste (default `token`); description is set to the label.
- **171-row cabinets**: per-cabinet filter over label + description, and a compact single-line row (label, description, kind, health, Show/Remove). A row whose description equals its label renders the label once.
- **Nav**: the mobile nav wraps instead of scrolling, so Keys is always reachable.

No change to `src/server/confirm.ts`, the challenge store, or any other gated route. Existing test ids (`view-vault`, `confirm-code-value`, `confirm-code`, `mfa-code`, `one-time-secret`) are preserved; the new `ConfirmGate` props are optional so its other four consumers are unaffected.

**Deferred:** the "stay unlocked this session" toggle. The bulk route removes the repeated-typing pain for the actual workflow, and an in-memory plaintext-secret holder adds surface for no remaining benefit.
