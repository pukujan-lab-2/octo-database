## Summary
- Adds `src/lib/relay-egress.ts`: pure helpers that pull a working key from Bearer/Basic/`x-api-key`/path/query, build the upstream request for each stored auth scheme (`bearer`, `x-api-key`, `basic`, `query`, `body_json`, `path`), classify the upstream status, and redact working keys from logs.
- Adds `src/routes/vault-relay.ts`:
  - `ANY /api/vault/relay/<routeKey>/<rest…>` — resolves the lease, decrypts the vendor secret, injects it upstream, streams the response back.
  - `POST /api/vault/lease/renew` — extends a working key's TTL.
  - `GET /api/vault/lease/info` — introspection for the key holder.
- Registers the relay family **before** `handleVaultRoutes` (which claims every `/api/vault` path and 404s unknown subpaths) and allows `x-api-key` in CORS preflight.
- The working key is stripped from every position the scheme does not use, so it cannot reach the vendor even if the caller puts it in the wrong place. Two different keys in two positions is refused rather than guessed.
- Upstream origin is always the stored route's origin; the caller controls only the path suffix and query.
