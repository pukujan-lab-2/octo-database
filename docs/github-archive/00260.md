## Summary
- **Per-item routes.** Each `token`/`login` row in the cabinet opens a disclosure listing its stored routes (route key, base URL, scheme, health pill with the health detail as a tooltip), a copyable relay URL, a remove action, and an add form that swaps the extra field for the chosen scheme (`authHeader` for `x-api-key`/`query`, `bodyField` for `body_json`/`path`, `basicUsername` for `basic`, optional explicit `routeKey`).
- **Working keys panel.** Lists leases with item label, name, prefix, live/expired/revoked state, expiry and last use, and revokes one in place.
- **URL kind.** When the item kind is `url`, a `urlKind` select appears (`api_base`, `api_endpoint`, `docs`, `console`, `cors`, `s3_endpoint`) and is sent with the item; it resets when the kind changes away from `url`.
- **Friendly errors.** `WORKING_KEY_*`, `LEASE_*`, `ROUTE_*`, `ITEM_REQUIRED`, `ITEM_NOT_ROUTABLE`, `BODY_TOO_LARGE`, `URL_KIND_INVALID`, and an `EGRESS_*` prefix fallback in `frontend/src/lib/api.ts`.

All mutating calls reuse the page's existing confirmation gate (single-use code, MFA when enrolled) and invalidate the routes/leases queries on success.
