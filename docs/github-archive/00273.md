## Summary

- The 6-character confirmation code lives in the API process's memory, so a deploy or restart wipes the code already on screen. For an account that never set a stored confirmation secret, the next save fell through to `412 CONFIRM_SECRET_NOT_SET` and dead-ended on setup the person did not ask for.
- `confirmGate` now issues a fresh code when no stored secret exists and no live code matches, answering `CONFIRM_CODE_INVALID`. The page already handles that by refreshing the displayed code and reopening the confirmation dialog.
- The Keys page no longer opens the set-a-confirmation-secret dialog; the one-time code is sufficient on its own.
