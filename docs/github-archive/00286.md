## Summary

Closes #285. A grant could list the cabinet but could not mint a working key for any item imported without a url — the common imported-token case (74/170 items in the owner's cabinet). It answered `400 ROUTE_REQUIRED` with no machine-readable detail, and the owner-only item/route endpoints answered a generic `401` that read like session expiry.

- `POST /api/vault/open/lease` now accepts `baseUrl` (plus `authScheme`, `authHeader`, `bodyField`, `basicUsername`) for a route-less item. The vendor URL is validated by the existing `parseVaultRoute`, the derived route is persisted owner-visible, and later leases reuse it. Precedence: explicit route → lease-time `baseUrl` → item `url`.
- `ROUTE_REQUIRED` now carries `code`, `itemId`, `itemLabel`, and `requires: "baseUrl"` so an agent can tell the missing prerequisite apart from a bad label or expired grant.
- Vault item/route/grant endpoints answer `403 FORBIDDEN` to a grant (a scope limit) instead of the generic `401`.
- `docs/consuming-octo.md` documents the new lease-time path.
