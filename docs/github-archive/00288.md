## Summary

Slice 7 was a packet with no engine. This makes it real end to end.

- **Catalog:** `octo.datasets`, `octo.dataset_versions`, `octo.analytics_results` (RLS + the Slice 14 RESTRICTIVE tenant fence, DML granted to `octo_service` only).
- **Registration:** `POST /api/workspaces/:id/datasets` validates the declared schema against every Parquet footer, sums row counts, assigns the next version under a lock, and writes the bytes to server-derived keys.
- **Query:** `analytics_query` jobs run DuckDB in-process in the existing worker drain path. The caller names `job-failures-by-type-month@1`; never SQL or an object key. The result Parquet is written, hashed, and registered.
- **Reads:** job status and result metadata, with a presigned R2 URL in production and an authenticated content route on the local backend.
- **Agent surface:** four MCP tools (`register_dataset`, `query_dataset`, `get_analytics_query_status`, `get_analytics_result`) and capability discovery for all four actions.
- **Docs:** `docs/consuming-octo.md` gains a full adopter section; the slice packet is locked and aligned with the implemented staged-parts design.
