## Why the server changed

An inline `<video>` needs two things the static route did not provide. `.mp4` had no content type, and ranged requests were answered with the whole body. Safari refuses to play a video in that situation, which would have broken the phone layout the page is built around. `sendStaticFile` now honours a single `bytes=` range with `206` and `Accept-Ranges`, and falls back to the full file for anything else. Two unit tests cover the 206 and the 416.
