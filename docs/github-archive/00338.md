### Symptoms

Film claim vs. code (`src/routes/vault.ts`, `src/routes/vault-relay.ts`, `src/lib/vault-policy.ts`, `db/migrations/2026101*_vault_*.sql`):

1. **Setup key "dies in minutes".** Grants last 5 to 72 hours (`GRANT_MIN_HOURS = 5`, `GRANT_MAX_HOURS = 72`). Not met.
2. **A key per service.** A lease is scoped to one vault item with proxy routes. Largely present.
3. **Auto-renewing keys.** Only a manual `POST /api/vault/lease/renew` called by the key holder; leases run 1 to 30 days (`LEASE_MIN_DAYS`, `LEASE_MAX_DAYS`). No scheduled renewal. Not met.
4. **Key dies with the job.** Nothing ties a lease to a job. Expiry or revoke only. Not met.
5. **Live access logs per key.** Only a `last_used_at` column on grants and leases. No per-use record of source, route or method. Not met.
6. **Leak detection and notification.** No anomaly check or notification in the vault routes. Decoy grants exist (`POST /api/vault/open/decoy`) but nothing alerts on them. Not met.
7. **Rotation from one dashboard.** Lease revoke and grant delete exist; a rotate-this-minted-key action does not. Partly met.
8. **Revoking a grant kills every key it minted, in every project.** Revoke exists; coverage of all minted keys not verified.
9. **Store once, proxy, inject at the edge.** `vault-relay.ts` provides proxy and relay routes. Appears present; not exercised.
10. **Figures on the page (28.6M leaked secrets, up 34%, 8 copies per secret).** Sources not checked.

### Hypotheses (unverified)

- **H1** *(hypothesis)*: auto-renewal and a short-TTL setup key can reuse the existing lease and grant tables with a TTL floor change and a renewal tick in `startSchedulers`.
  - Would refute: renewal needs a stored long-lived credential, which defeats "nothing that survives setup can reach the vault".
  - Experiment: trace what proves the renewer's identity at renewal time.
- **H2** *(hypothesis)*: per-use logging can be added where the relay already updates `last_used_at`, as an append-only row per call.
  - Would refute: relay volume makes per-call rows too costly, or source IP is not reliably available behind the deployment's proxy.
  - Experiment: check which client address the relay sees on the live instance.
- **H3** *(hypothesis)*: "unknown location" needs a baseline per key (first-seen sources) rather than a general anomaly engine.
  - Experiment: define the smallest rule that would have flagged a copied key.

### Counter-signal

The core "keep the secret home, proxy the call" model is implemented, so the film's central story is not hollow. Leases and grants already expire and can be revoked.
