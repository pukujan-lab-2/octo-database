## What

Gives a workspace its own analytics, per the platform-services analytics plan.

- Any dataset schema can be registered (the `job_failures` column requirement moves to query time for the built-in spec).
- **Workspace specs:** `POST/GET /analytics/specs` registers one SELECT over the view `data` with typed `$params`, stored as immutable `ws:<slug>@<n>`. DuckDB is locked (`allowed_paths`, no external access, locked config) before the SQL runs, so a spec can read only the mounted dataset parts.
- **Append:** `append: true` on dataset registration adds new date partitions as the next version without re-uploading earlier ones. `dataset: <slug>` on a query uses the newest version, pinned at submission.
- **Schedules:** `POST/GET/DELETE /analytics/schedules` runs a spec every N minutes when a new dataset version exists and writes rows to `analytics.<table>` in the workspace database (replace or upsert) as the workspace's own role, in one transaction.
- Two migrations, capabilities entries, docs in `docs/consuming-octo.md`.
