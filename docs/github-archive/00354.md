After you type the confirmation code (and the authenticator code, if MFA is on) once, the next changes for two minutes go through without asking again. The owner asked for this because every change was asking for both codes.

- **Server** (`src/server/confirm.ts`, `src/auth/confirm-challenge.ts`): passing the full gate opens a 2-minute window for that person. Inside it, a request that sends **no** codes passes. A request that sends codes still has them checked, so a wrong code or a reused recovery code is still refused. API keys are still always refused.
- **Web**: the API client remembers the window after a successful confirmed request. While it is open, the confirmation box shrinks to "Confirmed — no codes needed for the next 1:42", and the code fields stay hidden until it runs out.
- **Tests**: a unit test for the window, and an end-to-end test checking that a change without a code passes inside the window while a wrong code is still refused. The bulk-delete test no longer expects a missing code to fail right after a confirmed save. The shared `typeConfirmCode` helper skips typing while the window is open.

The window is in memory, so a server restart closes it and the code boxes come back.
