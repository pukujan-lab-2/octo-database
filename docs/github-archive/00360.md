# Issue #360: [ISSUE]: Agents cannot act as their user without a server-config shortcut — "act as me" keys with expiry and per-key powers

### Summary

**Proposal** *(none of this exists yet)*: every user can mint **"act as me" agent keys**. Each key works as that user's signed-in session, with:

- an **expiry** (hours or days) and **instant revoke** from the keys page, with no restart;
- **per-key powers**, e.g. vault read, vault write, deploy, confirm destructive actions, delete workspaces. A key can never do more than its user can.

This replaces the owner-only stopgap from #358, where an account-wide key listed in the server env var `OCTO_OWNER_AGENT_KEYS` acts as the owner. That list only works for the owner and needs a restart to change.

### Identity and Lineage

- Leaf issue: this issue. Related: #358 (stopgap), #334 and #338 (credential-plane gaps), #184 (agent grant).
- Order: first of the easy-access work. Env pull, the deploy helper, and access logs build on it.

### Symptoms

1. One account-wide key per principal is enforced by the unique index `uq_api_keys_account_wide`. A second key cannot be minted. *(verified on production 2026-10-30)*
2. API keys are refused by the vault (`src/routes/vault.ts`) and by `confirmGate` (`src/server/confirm.ts`), so an agent cannot add a secret or confirm an action without the stopgap. *(verified)*
3. The stopgap is configured per server, not per user. *(verified)*

### Proposed shape (hypothesis)

- A column on `octo.api_keys` marks a key as acting-as-owner, with its powers. The existing `expires_at` sets its lifetime. The unique index is relaxed for these keys.
- `authenticateRequest` treats such a key like the stopgap does today, gated by its powers. `confirmGate` passes only if the key has the confirm power.
- The key form gets an "act as me" checkbox, power toggles and an expiry.
- Once shipped, remove `OCTO_OWNER_AGENT_KEYS` and convert the owner's key.

### Acceptance Criteria

- [ ] Any user can mint, list and revoke expiring "act as me" keys. (proposed)
- [ ] A key without the vault-write power is refused on vault writes; one with it succeeds without codes. (proposed)
- [ ] An expired or revoked key fails on its next request. (proposed)
- [ ] `OCTO_OWNER_AGENT_KEYS` is removed. (proposed)
