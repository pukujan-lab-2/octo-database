### Summary

**Parked by the owner until every easy-access requirement is met.** This is the security-monitoring side of the credential plane: how Octo notices a stolen key or leaked data and tells the owner.

- **Per-use access log per key:** which key, when, from where (IP/ASN), which route and method. Today only `last_used_at` exists.
- **Leak alerts to the owner's phone** (ntfy, the same channel as the platform alerts):
  - a decoy key used (decoys exist via `POST /api/vault/open/decoy`, but nothing alerts);
  - a key used from a new place;
  - a sudden spike in use;
  - use after revoke.
- **Canary records and files:** fake entries that alert when opened.
- **Rotation from the dashboard**, and **short-lived, auto-renewing keys** that die with their job. Both are already described in #334 and #338; this issue only schedules them in the security phase.

Phase 6 status (Pukujan-lab/server-management#17), 2026-10-30. Nothing in this issue is implemented. It stays parked until the owner accepts a slice.

**Done around it (machine level):**
- CrowdSec with an nftables bouncer on gravebuster.
- Alert-only CrowdSec over octo-web's access log on the Pro (`crowdsec-pro` Komodo stack).
- `host-watch` on both machines: alerts on new users, admins, exposed ports, services and SSH keys.
- Everything alerts to the phone-ntfy topic. Tailscale and the home LANs are allowlisted.

**#338 H2 (which client address the relay sees):** before #374, octo-api saw only the cloudflared container (172.21.0.3) for every call. #374 makes Caddy trust `Cf-Connecting-Ip` from private peers only and forward the real caller as `X-Forwarded-For`. Once it is in production, per-use logging can read the source IP from that header.

**Proposed smallest slice for the owner to accept or change:**
1. An append-only `octo.agent_key_uses` row (key id, time, source IP from X-Forwarded-For, route, method), written where `last_used_at` is updated today.
2. Two ntfy alerts on top of it, both rules that need no baseline:
   - a revoked or expired key presented;
   - a key used from an IP outside the set seen in its first 7 days (H3).
3. Real decoys: today `/api/vault/open/decoy` mints a narrowed grant, not a tripwire. A decoy that alerts on any use would be a new grant flag; that waits on owner direction.
