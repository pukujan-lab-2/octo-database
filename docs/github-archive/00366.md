## What changes

**Chunk gaps (#357).** The next chunk now starts where the previous one actually ended, minus the overlap. Before, an early break left text in no chunk. The chunker is renamed `paragraph-aware-v2`, so old rows can be told apart. `scripts/reembed-rag.ts` re-indexes every text version under the new config. A unit test now covers inputs with early breaks.

**Document filter (#364).** `POST /api/rag/query` accepts `filter: { documentIds?, titlePrefix?, latestVersionOnly? }`. The filter is applied inside both search arms, before their limits. The filtered vector arm scans exactly, because the HNSW index would drop matches.
- Every match now also returns `documentId`, `title`, `versionNumber` and `page`.
- The MCP `query_workspace` tool has the same filter.
- Migration: `20261030020000_rag_query_filter_and_pages.sql`.

**Uploaded files are searchable (#365, #227).** A new `rag_ingest_file` queue job does the indexing:
- **PDFs with a reader:** each page is rendered (poppler) and read by PaddleOCR-VL. The reader is set by `OCTO_READER_URL`: any OpenAI-compatible server, here llama.cpp `llama-server`.
- **Passages:** page Markdown becomes passages, and table rows stay one per line with their header repeated. HTML, OTSL and pipe tables are all handled.
- **Number check:** a passage with a number that isn't on that page's text layer is not indexed. Scans have no text layer, so their passages are kept as read. The two-reader check for scans is not built.
- **PDFs without a reader:** each page's text layer is chunked. PDF chunks always record their page.
- **When indexing runs:** PDF and text uploads are queued automatically when embeddings are configured. `POST /api/rag/documents` with `fileId` returns 202 and the job id; the MCP `ingest_document` tool takes `fileId`.
- **Docker image:** `Dockerfile.api` now installs `poppler-utils`.
