Adds part 3 of #365, which was closed without it.

- When `OCTO_RERANK_URL` is set, every `POST /api/rag/query` is reranked: Octo pulls a wider hybrid candidate set (3× the limit, 30–100), re-scores it with a cross-encoder at `OCTO_RERANK_URL` (`/v1/rerank`), and returns the top `limit`.
- `rerank: false` skips it for one query. The response shape is unchanged except that each match gets `rerankScore` and the response gets `reranked: true|false`. `false` means no reranker answered, so the hybrid order is kept.
- `rerank: true` with no `OCTO_RERANK_URL` set → 503 `RERANK_NOT_CONFIGURED`.
- The `query_workspace` MCP tool passes `rerank` through.
- Env: `OCTO_RERANK_URL` (comma-separated URLs, tried in order), `OCTO_RERANK_MODEL` (default `bge-reranker`).

On the Pro, bge-reranker-v2-m3 (Q8) runs behind llama-swap at `127.0.0.1:8095`, LaunchAgent `com.octo.rerank`. It starts on demand (16 s cold, instant warm), uses about 0.8 GB while loaded, and stops after 5 idle minutes.
