# Issue #385: octo-graph has no volume: recreating the container erases the graph

- State: closed (2026-11-01)
- Opened by Pukujan on 2026-10-31
- Original: https://github.com/Pukujan-lab/octo-database/issues/385

## What happens

`octo-graph` (FalkorDB 6.0.1) has no volume. Its save file is `/var/lib/falkordb/data/dump.rdb` inside the container's own layer (last written 2026-10-18 on the Pro). Recreating the container, for example on an image update or a `compose up --force-recreate`, erases the graph.

Checked 2026-10-31 on the Pro: `docker inspect octo-graph` lists no mounts.

## Work requested

Mount a named volume at `/var/lib/falkordb/data` in `deploy/gravebuster/docker-compose.yml`, copy the current `dump.rdb` into it before the first recreate, and confirm the graph survives a recreate.

The graph is small today (about 70 KB) and can be rebuilt from files, so this is cheap to fix now.
