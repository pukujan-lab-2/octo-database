# Issue #387: Store each file's bytes once in R2 using content_hash

- State: open
- Opened by Pukujan on 2026-10-31
- Original: https://github.com/Pukujan-lab/octo-database/issues/387

## Why

Files are stored once per upload. On the Pro, 2026-10-31: 1,837 file rows but 1,722 distinct `content_hash` values. Small today; at scale the same PDFs, templates and exports repeat across workspaces.

## Work requested

Use the existing `octo.files.content_hash` so uploads with the same contents point at one R2 object (reference-counted, deleted when the last file using it goes). Access control stays per file row; only the bytes are shared.
