# Issue #392: Small reranker on the always-on server as the last fallback

- State: open
- Opened by Pukujan on 2026-10-31
- Original: https://github.com/Pukujan-lab/octo-database/issues/392

## Why

Reranking (#365) runs `bge-reranker-v2-m3` on the GPU machines: Windows first, then the Pro (`OCTO_RERANK_URL` lists them in order). When both are off, queries fall back to plain hybrid order.

The always-on server (OVH SYS-1, CPU only) can't run `bge-reranker-v2-m3` usefully: an estimated 3-8 s for 30-100 passages. A small cross-encoder can.

## Work requested

Run a small reranker on the server as the last URL in `OCTO_RERANK_URL`, so reranking still works when both GPU machines are off.

- Model: `cross-encoder/ms-marco-MiniLM-L-6-v2` (about 22M parameters) or similar, served with a `/v1/rerank` endpoint (llama.cpp `llama-server --reranking`, as on the GPU machines). Estimated 0.2-0.5 s for 50 passages on that CPU.
- `OCTO_RERANK_MODEL` is one name for every URL (`src/rag/rerank.ts`). Either serve the small model under the same name on the server, or let each URL carry its own model name. Pick the smaller change.
- English-only is acceptable for now; the big model stays the first choice.

## Done when

With the Windows PC and the Pro off, a `/api/rag/query` on the server comes back with `reranked: true` in under about a second for a normal limit.
