# Issue #395: Shared model endpoints: embed and rerank for other projects

- State: open
- Opened by Pukujan on 2026-10-31
- Original: https://github.com/Pukujan-lab/octo-database/issues/395

## Why

Octo already runs one embedder (`octo-embed`, `qwen3-embedding:0.6b`) and one reranker (`bge-reranker-v2-m3` via `OCTO_RERANK_URL`) that every workspace's RAG uses. Other projects load their own copies instead. Precedent's legal engine (Pukujan/legal-graphrag-starter) loads `bge-small-en-v1.5` and `ms-marco-MiniLM-L-6-v2` into its own process because Octo offers no way to call the shared ones. Host once, share to many.

## Work requested

Two endpoints for any workspace API key, passing through to the models Octo already runs:

- `POST /api/models/embed` `{ input: string[] }` → `{ model, embeddings: number[][] }` (calls `OCTO_EMBEDDING_BASE_URL`).
- `POST /api/models/rerank` `{ query, documents: string[] }` → `{ model, scores: number[] }` (same fallback chain as `src/rag/rerank.ts`, including #392 once it lands).

Reuse the existing embedding and rerank clients; no new model servers.

## Done when

From another project with a workspace key, both calls return results through `octodb.design-bakery.com`, and the legal engine can use them (see the linked engine issue).

Related: #365, #392.
