# Issue #399: RAG query: optional graph step (hybrid + graph) shared by all workspaces

- State: open
- Opened by Pukujan on 2026-10-31
- Original: https://github.com/Pukujan-lab/octo-database/issues/399

## What

Octo's RAG search (`/api/rag/query`) is hybrid only: word match (BM25) plus meaning match (HNSW), merged by RRF, then reranked. It never uses the graph.

Precedent's legal engine adds a graph step, and that step finds cases that neither the words nor the meaning would find:

1. hybrid search, then the top 10 results become seeds;
2. walk the `cites` edges from those seeds (personalized PageRank, `legal_graph/graph_scoring.py`);
3. merge the text list with the graph list by weighted RRF;
4. rerank.

Today that step lives only inside the legal engine, as an in-memory networkx graph. Any other project that wants hybrid + graph has to build it again. That goes against "host once, share to many".

## Proposal

Add an optional graph step to `/api/rag/query`, for example `graph: { edges: ["cites"], seeds: 10, hops: 1 }`:

- Seeds are the documents behind the top hybrid hits.
- Neighbours come from the workspace's graph (FalkorDB `octo-graph`, or an edge table if that is simpler).
- The neighbour list is merged with the hybrid list by RRF before the rerank.
- Off by default; on for a workspace that has edges.
