# PR #404: fix(vault): relay never returns the stored secret on redirects or echoes

A working key could reveal the stored secret through a vendor redirect. This closes that.

- **The leak:** with a `query`-scheme key the relay adds the secret as `?key=`. MTA Bus Time answers `vehicle-monitoring.json?…&version=2` with a `302` whose `Location` repeats the whole query, secret included. The relay passed that through unchanged, so anyone holding only the `octo_tmp_` key got the real one. The relative `Location` also pointed the caller back at Octo's own host.
- **Redirects:** `forwardUpstream` now follows same-origin redirects itself, up to 5 hops, with the secret re-injected. The caller gets the final answer. A redirect to another origin is never followed (it would send the secret to another host). It goes back as a `3xx` with an absolute `Location`, scrubbed of the secret. `301`/`302`/`303` on a non-GET become a bodyless GET. A `307`/`308` whose body was streamed (so it can't be replayed) is passed back, not followed.
- **Scrubbing:** every response header and the streamed body are filtered for the raw secret, its URL- and form-encoded spellings, and the Basic credential. Each one is replaced with `octo_secret_redacted`. The body filter handles a secret split across chunks and leaves binary bytes untouched. Secrets shorter than 8 characters are not scrubbed from bodies, because replacing a very short string would corrupt every response.
- **Both paths:** `/api/vault/proxy` and `/api/vault/relay/<route>` share `forwardUpstream`, so both get the fix. The new logic (`secretForms`, `scrubSecrets`, `createSecretScrubber`, `planRedirect`) is pure code in `src/lib/relay-egress.ts`.

Tests: `tests/unit/vault-relay-redirect.test.ts` runs a local vendor that redirects (relative, same origin, with the secret in `Location`, like MTA), redirects cross-origin, loops, and echoes headers and query in both headers and body. It runs for `query`, `x-api-key`, `bearer` and `basic`, through both entry points (24 cases). It checks that the vendor received the secret on the followed hop and that no spelling of it reaches the caller. Against the old code, 22 of 24 fail. The two that pass are header-scheme cross-origin hops, which never carried the secret. Pure-helper cases are in `relay-egress.test.ts`. Locally, `npm test` (544), `typecheck` and `lint:imports` pass. Fixtures only, no real secret.

`docs/consuming-octo.md` gains one paragraph on the new redirect behavior.
