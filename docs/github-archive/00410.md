# Issue #410: Claude Code sessions here held commits for a go-ahead, kept auto-merge off and asked the owner to merge, because the rules are text and nothing enforces them

- State: open
- Opened by Pukujan on 2026-10-31
- Original: https://github.com/Pukujan-lab/octo-database/issues/410
- Labels: observational-issue, proposal, account:owner, needs-filer-stamp, needs-impact-evidence, needs-record-context, needs-release-relevance, ontology:project-1.0.0, type:observational, status:open, ontology:oio-1.1.0, relation:related, priority:3

### Summary

Claude Code agents here had `AGENTS.md` in context and still broke it in ten audited cases (2026-10-30 to 10-31). Claude Code's own defaults won: "commit or push only when asked", end-of-turn approval questions (80 of 132 ended with one), worktrees inside the checkout. A brief written by another Claude session ("don't merge … without the owner's OK") was obeyed over the rule that auto-merge is mandatory. The fix is enforcement from the stack's guard hooks ([agent-stack-train#37](https://github.com/Pukujan/agent-stack-train/issues/37)), installed here.

### Identity and Lineage

- related: Pukujan/agent-stack-train#37 (the stack's rules are only text; the guard that enforces them)
- related: Pukujan/agent-stack-train#34 (the installer never wired `AGENTS.md` into Claude Code)

### Acceptance Criteria

1. This repository carries the stack's guard: `.claude/hooks/acs_guard.py` and its SessionStart, PreToolUse and Stop hooks in `.claude/settings.json`, installed by `acs_install.py` from a certified stack commit.
2. `CLAUDE.md` carries the stack's bridge region, including where the rules beat Claude Code's defaults.
3. CI fails when either is missing (`hotload_check`, and `check-adopter` with `claude: require`), and fails a pull request that names no owning issue.
4. A Claude Code session here is blocked when it commits without an owning issue, pushes to `main`, makes a worktree inside the checkout, or stops with unpushed or uncheckpointed work.

### Boundaries and Next Action

- Changes only the stack's installed files and CI wiring here; no product code.
- Next action: when agent-stack-train#36 merges and the train certifies the next version, take the upgrade pull request the train's bot opens, set `claude: require`, and confirm the guard blocks a test push to `main`.

### Symptoms

1. **Auto-merge kept off.** Session 77ec749c opened PR #404 as a draft "so the repo's auto-merge backstop doesn't arm it", against the rule that every PR arms auto-merge.
2. **Owner asked to merge.** 77ec749c and 61973c24 asked the owner to mark PRs ready and merge, which the rules forbid.
3. **Work held for a go-ahead.** 9328ebf5 spent five turns "taking no action" with a ready commit until the owner typed "yes, skip on outage".
4. **No checkpoint for about 20 PRs.** `CURRENT.md` was last updated on 10-26 while about 20 PRs merged.
5. **Worktree inside the checkout.** 77ec749c ran in `.claude/worktrees/sharp-cartwright-65ba50` inside the checkout.

### Hypotheses (unverified)

- **H1: text loses to Claude Code's built-in defaults.** Status: confirmed in the audit for octo-database; inferred here. Would confirm: breaks stop once the guard blocks them. Would refute: the same breaks recur with the guard installed. Experiment: run one sample task with the guard installed and count blocked actions.
- **H2: stale or missing local rules.** Status: confirmed where sessions started on a branch without the current `AGENTS.md`. Would refute: sessions on an up-to-date `main` break the rules at the same rate.

### Counter-signal

Sessions that started from an up-to-date `main` with the rules loaded followed most of them, so text alone works some of the time. The guard must not block work that already follows the rules.

### Honest Caveat

The audit read Claude Code transcripts on one Mac. The desktop app's own instructions are not stored in transcripts, so their share of the breaks is inferred from timing and wording. Codex sessions were not measured.

### Problems vs Gaps

- Problem: agents break the PR, checkpoint, worktree and issue-log rules in Claude Code (symptoms above).
- Gap: nothing installed here enforces the rules; they are text only.

### Proposal *(proposal)*

Nothing here exists yet in this repository. Install the stack's guard and bridge through the train's upgrade pull request, then require them in CI.
