## Summary

Other repositories now keep their data in Octo, so one claim matters above the rest: no workspace can read or change another's data, and HTTP, MCP and SQL all enforce the same rules. The tests check this route by route, written by hand, so a new route or tool can ship without any isolation check. This issue sets the checks the owner asked for and what each must pass.

## Observed facts

- e2e suites carry hand-written metamorphic cases (MR-1 to MR-7) in 10 files; there is no generated coverage over the `ROUTES` table or the MCP tool list.
- The repository has no TLA+ or Lean. The stack train already model-checks a TLA+ spec in its own CI.

## Proposal

*(proposal)* Four parts, each its own pull request:

1. **Generated isolation tests.** Enumerate every HTTP route and MCP tool. Call each with another workspace's key, a read-only key (for writes), a revoked key and a guest. Each must be refused. A new route or tool is covered without editing the test.
2. **Metamorphic tests for RAG and the graph.** Adding another workspace's documents never changes my results. Turning rerank on only reorders results; it never adds one that filters excluded. Projecting the same rows twice gives the same graph.
3. **Small TLA+ specs, model-checked in CI,** for workspace creation (a duplicate request makes one workspace), the file lifecycle and archive worker, and key revocation against an in-flight request and the confirm window.
4. **`docs/PDD.md`** names these properties as the contract the tests check.

Lean 4 is left out on purpose: it would prove a model, not the TypeScript and SQL that run, and TLA+ covers the model more cheaply.

## Acceptance criteria

- [ ] Part 1 runs in `gates` and fails when any route or tool answers another workspace, a revoked key or a guest with success.
- [ ] Part 2 runs in `gates` with the three relations above.
- [ ] Part 3: three specs, each with its invariant, model-checked by TLC in `gates`.
- [ ] Part 4: PDD lists each property and the test or spec that checks it.

## Boundaries / non-goals

- No new isolation mechanism. Tests report defects; fixes get their own issues.
- No Lean 4.
