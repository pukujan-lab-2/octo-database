Nothing checked that every route and MCP tool refuses a caller from another workspace, so a new route could ship without its workspace check.

## Problem and consequence

Octo now serves several repositories from one instance, and isolation was tested only where a slice happened to add a case. About 120 routes and 35 MCP tools had no common check. Building this check turned up a real defect: the workspace-delete handler claimed every `DELETE /api/workspaces/...` path, so `DELETE /api/workspaces/:id/analytics/schedules/:id` always answered 400 and an analytics schedule could not be removed.

## What changes

- `tests/e2e/route-table.ts`: every route, with its tenancy (workspace, principal, session-only, own token, public), the scope it needs, and where it reads the workspace id.
- `tests/e2e/route-isolation.spec.ts` generates the cases from that table. Against one guest's workspace:
  - no credential gets 401, and a revoked key gets 401;
  - another workspace's key gets 403, and a non-member's session gets 403, or 404 `WORKSPACE_NOT_FOUND` where row-level security hides the workspace;
  - a read-only key gets 403 on every route that needs more;
  - the vault refuses every API key.

  A second person cannot see, re-scope or revoke someone's key. Every workspace MCP tool, called with another person's key or session, comes back refused. A read-only key's tool list holds only tools its capabilities allow, and a revoked key cannot reach `/mcp`.
- `tests/unit/route-table-drift.test.ts` reads the route matchers in `src/routes` and `src/server/oauth.ts` and fails when one has no row. It caught two vault lease routes I had missed.
- `src/routes/workspaces.ts`: the workspace-delete handler matches only `/api/workspaces/<id>`.
- `docs/ARCHITECTURE.md`: the UX analytics route is `POST /api/workspaces/:id/ux-analytics` (the docs PR said `/enable`), and new endpoints need a table row.

## Before and after

Before: isolation was checked route by route, where someone remembered, and the schedule delete route could not be reached.
After: 327 generated cases cover every row, a missing row fails the unit tests, and the schedule delete route works.
