Search and the graph had no test that another workspace's data leaves a workspace's results alone, or that rerank and filters can only take away.

## Problem and consequence

The existing hybrid-search spec checks that another workspace's chunks never appear. It does not check that they leave the ranking untouched, and nothing covered reranking or the filters as relations. The graph rebuild test compared counts only. A change that let another workspace's data shift scores, or let rerank pull in a filtered-out result, could pass.

## What changes

- `tests/e2e/rag-graph-metamorphic.spec.ts`:
  - MR-S1: seed another workspace with documents that match four queries better. This workspace's results stay identical: same chunks, order and scores.
  - MR-S2: a filter by documents or title prefix returns a subset of the unfiltered matches, and every match passes the filter.
  - MR-G1: projecting twice gives the same graph, comparing every node and edge with their properties, not counts.
  - MR-G2: another workspace records the same names and projects; this workspace's graph does not change.
- `tests/unit/rerank-metamorphic.test.ts`: 200 seeded cases show rerank only reorders. It never adds, drops or changes a result, ties keep the hybrid order, and the cut keeps the top scores. Rerank server answers that arrive shuffled or partial still line up with their documents.
- `src/rag/rerank.ts` and `src/routes/rag.ts`: the rerank sort moves out of the route into `applyRerankScores`, unchanged, so the unit test drives the same code the route runs.

## Before and after

Before: isolation in search was "never returns their chunks", and graph rebuilds were compared by count.
After: search is shown to be independent of other workspaces, filters and rerank only take away, and rebuilds are compared node for node.
