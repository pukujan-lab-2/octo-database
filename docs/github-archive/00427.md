# Issue #427: Auto-merge here does not check who wrote the pull request

- State: closed (2026-11-01)
- Opened by Pukujan on 2026-11-01
- Original: https://github.com/Pukujan-lab/octo-database/issues/427

This repository's `auto-merge.yml` arms auto-merge on every same-repository pull request without checking who wrote it, so a future collaborator's pull request would merge with no review.

The owner decided (2026-11-01) that auto-merge stays on, but only for pull requests from the owner and trusted collaborators. Today that means the owner and the owner's agents, which act through the owner's account. The stack-wide part is Pukujan/agent-stack-train#91.

## Symptoms

1. **Any author is armed.** The workflow's only conditions are "not a draft" and "not a fork".
2. **A later push is not checked.** A push by someone else onto an armed pull request still merges.

## Hypotheses

**H1: trusting the repository's admins plus a repository variable `AUTO_MERGE_AUTHORS` covers the owner with no setup.**
- **Status:** confirmed for the owner: `Pukujan` is `admin` here (`gh api`); a stranger gets `read`.
- **Would refute:** the workflow token being unable to read collaborator permissions (then nothing arms, and the notice says so).
- **Experiment:** the first pull request after the change shows "Armed squash auto-merge".

## Evidence

- One collaborator today (`Pukujan`), so nothing is exposed yet.
- **Counter-signal:** none.

## Caveat

If the permission lookup fails, the workflow fails closed: it does not arm, and prints a notice.

## Proposal *(proposal)*

Arm only when the author and the pusher are trusted; turn auto-merge off after an untrusted push. Same change as Pukujan/agent-stack-train#92.
