On the live data, the new tables sorted empty rows to the top and the key use log split each vault item into its own route.

## Problem and consequence

Checked on production with the owner's account:

- Workspace databases opened sorted by size, biggest first, but the 17 workspaces with no database came first, because flipping the order also flipped where empty values go.
- The key use log had 755 rows, mostly `/api/vault/items/<uuid>` once per item.
- The key use log was wider than the page, so First seen and Last seen were cut off.
- Filter labels read "All key", "All role".

## What changes

- `frontend/src/components/portal/DataTable.tsx`: empty values sort last in both directions; filter labels read "Key: any".
- `src/server/db.ts`: `dbListKeyUseSummary` replaces UUIDs in a route with `:id` before grouping.
- `frontend/src/components/access/KeyUseLogSection.tsx`: one Last seen column with "since <first date>" under it; IPv4-mapped addresses (`::ffff:1.2.3.4`) show as plain IPv4; narrower route column.

## Before and after

Before: biggest databases sat below 17 empty rows, and the key use log had 755 rows and ran off the right edge.
After: biggest databases first, and the same key use data comes to 144 rows across all principals on the VPS, in a table that fits.
