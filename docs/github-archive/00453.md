### Summary

Octo runs its own Sablier (`octo-sablier`) inside its compose project. Pukujan-lab/server-management#85 moves Sablier to the host-wide `platform` stack, by the owner's decision, and sets idle time to 10 minutes. This log covers Octo's side: drop its Sablier, put `octo-web` on the shared `sablier` network, and shorten `session_duration` to 10m.

### Acceptance Criteria

- [ ] Phoenix, the embedder and legal-engine stop after 10 idle minutes and start on the next request
- [ ] `vps/services.toml` and the units in `vps/legal-engine/` say 10 minutes

### Symptoms

1. `ssh vps docker ps` on 2026-11-01: `octo-sablier` (sablierapp/sablier:1.19.1, compose project `octo`) is the only Sablier. Its command has no `--storage.file` and no `--provider.verify-enabled-on-expiration`.
2. Komodo `ListStacks` on 2026-11-01: `platform` is `down`.
3. Octo's `deploy/gravebuster/Caddyfile` (production 7c98cdd) calls `http://sablier:10000` with `session_duration 30m` on `/phoenix`, `:6006` and `:11434`.
4. legal-engine's proxy runs with `--exit-idle-time=20min`.

### Hypotheses (unverified)

- (hypothesis) Keeping the alias `sablier` on the shared network means Octo's Caddyfile URL needs no change.
  Experiment to confirm: after the cutover, a request to `:6006` from `octo-api` starts a stopped Phoenix.

### Counter-signal

none

### Honest Caveat

Octo's sessions in its current Sablier are in memory only, so the cutover forgets them. With `auto-warm-externally-started`, the new Sablier gives running containers a fresh 10 minute session.

### Problems vs Gaps

- Problem (evidenced): Sablier lives in one app's project, without session storage, and the shared stack is not running.
- Gap: idle times longer than the owner wants.
