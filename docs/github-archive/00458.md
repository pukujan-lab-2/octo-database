# Issue #458: Expose Phoenix datasets, experiments and projects through a workspace's otel routes

- State: open
- Opened by Pukujan on 2026-11-01
- Original: https://github.com/Pukujan-lab/octo-database/issues/458

### Summary

The website copilot lab (Pukujan-lab/voice-agent-research) wants to keep its evaluation cases and results in each workspace's Phoenix, using Phoenix's own datasets and experiments instead of a table of our own. Octo exposes only three Phoenix paths per workspace, so that is not possible through Octo today. This is a request only; nothing in this repository needs to change until Octo's owner decides.

### Identity and Lineage

Leaf: this issue (a request). Parent: none in this repository. Depends on: none. Related: Pukujan-lab/voice-agent-research#88 (the loop that wants it), #123's sibling work there, and the earlier Phoenix-through-Octo work (#268, #342, named in that lab's `demo/live-site/tracing.ts`).

### Acceptance Criteria

- (proposal) Through `/api/workspaces/<ws>/otel/...`, authenticated with the workspace key, Octo exposes the Phoenix REST routes for datasets (create, append examples, read), experiments (create, record runs and evaluations, read) and projects (list), so that `arize-phoenix-client` (Apache-2.0) can be pointed at the workspace.
- The routes stay scoped to the workspace's own Phoenix project, as the existing three are.

### Boundaries and Next Action

In scope: deciding whether Octo exposes these routes and which. Out of scope: any code change in the lab; the lab keeps its cases in an Octo table until this is decided. Next action: Octo's owner decides.

### Symptoms

1. **Datasets and experiments are not reachable.** With a workspace key, `GET /api/workspaces/<ws>/otel/v1/datasets`, `.../otel/v1/projects`, `.../otel/v1/experiments` and `.../otel/read/datasets` each answer 404 "Not found" (checked 2026-11-01).
2. **Only three Phoenix paths work.** `GET .../otel/read/spans` (needs a normal User-Agent, or Cloudflare answers 1010), `POST .../otel/v1/traces` and `POST .../otel/v1/span_annotations` answer normally.
3. **A direct Phoenix call is refused.** A GraphQL call with the Octo key returned "Invalid token" (reported by the lab's lead session, not re-checked here).

### Hypotheses (unverified)

- **H1. Octo proxies a fixed list of Phoenix routes and these were not added.** Status: unverified. Would confirm: the route table lists only the three. Would refute: the routes exist under another prefix. Experiment: read Octo's otel route table.

### Counter-signal

The lab can keep cases in an Octo table, which works today; Phoenix datasets would add experiment comparison and the Phoenix UI for results, not a new capability.

### Honest Caveat

I have not read Octo's code; the symptoms come from calls made with the chatbots workspace key.

### Problems vs Gaps

Gap: Phoenix datasets and experiments are unavailable to workspace users. Problem: none observed.
