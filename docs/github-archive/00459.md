# Issue #459: RAG: metadata filters (section, page type, language) and batch ingest for big sites

- State: open
- Opened by Pukujan on 2026-11-01
- Original: https://github.com/Pukujan-lab/octo-database/issues/459

## Problem

A business that puts a whole website into Octo cannot ask for "only the refund policy section, only FAQ pages, only Spanish" in a search, and cannot load passages quickly. `/api/rag/query` filters only by `documentIds`, `titlePrefix` and `latestVersionOnly`, and `/api/rag/documents` takes one document per call and embeds it before answering.

## What the copilot does today to get around it

The website copilot (Pukujan-lab/voice-agent-research, parent #107) loads each passage as its own document titled `<business>/<language>/<page type>/<id>`, keeps url, title, section and dates in a table in the workspace's own database, and narrows a search with `titlePrefix` (language, then page type) and with `documentIds` (the passages under one heading). That works, but:

1. **Only a left-to-right prefix can filter before the limit.** A page type without a language, or any second dimension, has to be checked on the results after Octo has already cut them to the limit, so recall drops when the filter is selective.
2. **`documentIds` has to be fetched first** from our own table (up to 500 ids) and sent back.
3. **One call per passage.** Measured on the live workspace on 2026-11-01: about 0.4 s per `POST /api/rag/documents` (one passage, one embedding). A 100,000-passage site is about 3 hours with 4 parallel callers, most of it round trips.

## Proposal *(none of this exists yet)*

- `metadata` (a small JSON object) on `POST /api/rag/documents`, stored with the document, and `filter.metadata` on `/api/rag/query` (equality on keys, applied inside both search arms before the limit), with a GIN index on the column.
- A batch form of `POST /api/rag/documents` (`documents: [{title, text, metadata}]`, up to 100) that embeds in one request.
- Optional: `DELETE /api/rag/documents?titlePrefix=…&workspaceId=…` so a business's site can be removed or reloaded in one call.

## Done when

A filtered search on section, page type and language returns in about the same time as an unfiltered one (see the filtered-search scaling measurements on #391), and a 10,000-passage site loads in minutes.
